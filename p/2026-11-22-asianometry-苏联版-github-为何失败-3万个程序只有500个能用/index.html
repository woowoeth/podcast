苏联版 GitHub 为何失败：3万个程序只有500个能用

苏联建立了国家算法程序库GosFAP试图解决软件重复造轮子的问题，但缺乏IBM式的硬件兼容标准和市场激励，最终沦为一座存满无用代码的「软件墓地」。

计算机史苏联开源协作软件标准化企业内部工具
一段冷门但细节扎实的技术史，讲清楚了标准化、兼容性和激励机制为何比「建个仓库」更重要，对理解今天的开源协作和企业内部代码复用也有参照意义。

核心论点 · 点时间戳可跳到原声

1:00

IBM 拆分软硬件催生了付费软件产业

1964年IBM推出System/360系列，实现了不同型号间的软件完全兼容，程序可以无需修改直接移植。1969年因担心反垄断诉讼，IBM将软硬件分开定价，诞生了「打包程序」产业——用户不再需要自己写程序或等厂商免费提供，而是直接购买。十年内，美国打包软件产业做到了十亿美元年收入，支撑了整个国家的计算机化浪潮。

3:03

内存稀缺逼得苏联程序员放弃高级语言

苏联第一代、第二代计算机内存从1个字到32000个36位字不等，相当于现在144KB左右，而IBM System/360 Model 65已有128KB到1MB内存。内存如此珍贵，使得苏联程序员大多放弃高级「算法语言」，因为编译器太占内存空间，转而用底层的autocode或汇编语言编程，程序先用铅笔手写，再用墨水誊写，然后两次打孔核对，每人每天只有一次上机运行的机会。

9:21

机器一装机就开始分化，软件跟着报废

苏联计算机出厂时完全一致，但安装后真空管、内存、输入输出等部件陆续损坏，维修改造导致每台机器逐渐偏离同类机型。由于程序代码都是机器级的，与运行机器紧密绑定，机器一变，软件就要跟着改，久而久之一个程序会变成连同系列机器都跑不动的「科学怪人」。塔什干中亚电网调度中心1968年换新机器，五年攒下的全部软件都要重写，几年后再换一次机型，又得重写一遍。

13:28

国家算法程序库本意是「公共图书馆」

1968年苏联正式启动国家算法程序收藏，定位类似「公共图书馆」或「计算机用户协会」，存取软件都不收费。但这个只靠捐赠维持的小机构很快被需求淹没，与此同时还存在各行业的「部门基金」和地区性的「地区基金」（如乌克兰共和国算法程序基金，取用要收「结账费」），彼此之间缺乏协调。

14:30

一万份程序里一半是过时或有缺陷的

1973年，莫斯科一计算中心实验室主任Galeev在《真理报》撰文批评：国家收藏的一万多份算法程序中，超过一半被认为过时或存在严重缺陷。对2000多份用于建筑工程计算的程序审计后，只发现123份能用。某个Minsk-22计算机的承重框架计算算法有18个变体，结果没有一个能正常运行。Galeev将此归因于资源不足——国家收藏运作多年仍只有五个人，仅够给新提交的程序分类归档，根本没精力先审核质量。

17:35

软件上的投入差距比硬件差距更致命

1970年代苏联通过照搬IBM System/360标准（Ryad/ES-EVM）统一了碎片化的硬件生态，顺带也能「接触」到西方软件——通过会议、期刊、西方软件库、面对面交流等渠道获取。但这种搭便车的方式反而让苏联国内软件产业缺乏必要投资：1980年美国每花一美元硬件就配套花一美元软件，苏联只花1.5到2美分。同期莫斯科国立大学到1976年仍只有两台BESM-6，而美国重点研究型大学通常拥有5到15台计算机。

19:40

国家图书馆的「复用率」只有美国的1/60

GosFAP成立十余年后收录了三万多份程序，但能用的只有500份，远低于当时美国可用的8000份高质量程序。一位苏联计算机技术与信息科学国家委员会委员1989年接受采访指出，美国程序的「平均复用率」是100次，苏联只有1.7次——说明苏联程序员几乎不花力气让程序能在自己开发机之外的机器上运行。

20:42

面对碎片化失败，苏联的答案永远是再集中化

西方观察者当时就批评，苏联对集中化失灵的回应从来都是「更集中化」：曾试图为某些编程语言制定「国家标准」，甚至立法规定不得更改语法，但标准总是迟迟定不下来，程序员只能继续各行其是。1989年那位委员会成员提出的解决方案GSPO（「国家软件系统」）设想由国家直接接管软件从开发到交付维护的全链条，认为GosFAP失败是因为国家管得还不够多。两年后，苏联解体。
