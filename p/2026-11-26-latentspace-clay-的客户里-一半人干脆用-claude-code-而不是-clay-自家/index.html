这家为销售团队做 AI agent 的公司明确表示不想让自家 agent 比「用 Clay 加 Claude Code」更好用，它想做的是 GTM 领域的底层基础设施，而不是又一个要垄断入口的聊天界面。

GTM engineer 是从「堆人」到「写系统」的转变

Jeff Barg 解释 go-to-market engineer 这个称呼的来源：2010 年代公司靠堆更多销售和市场人员来找客户，但 LLM 出现后，agent 可以自己去爬网、给客户打分、执行判断，于是出现了一批用软件工程方法做增长的人——写 prompt、做数据工程、搭自动化系统。这个角色融合了 agent 工程、数据工程和传统软件工程，此前这类工作大多落在 revenue operations 部门里，没有独立身份。

— Jeff Barg
25:34

没有 CRM 数据，agent 就是瞎子

Sculptor 第一版最大的短板不是模型能力，而是缺上下文：agent 拿不到 CRM 数据，也看不到一封 outbound 邮件发出去之后的真实结果，导致它没法像真正的销售代表那样做判断。团队为此重建了整个平台的数据层（Audiences），把 CRM、Gong 通话记录等第一方数据和 Clay 自带的公司数据集做实体对齐，变成一张「权威的客户与联系人大表」，agent 才有东西可用。

— Jeff Barg
29:45

post-training 只有在推理花费到千万级才划算

Jeff 说 Clay 过去 18 个月一直觉得自己训模型不现实，直到最近才开始考虑。他给出一个经验门槛：只有当推理花费达到大约 1000 万到 1 亿美元规模时，省下来的钱才「够重」（chunky），值得去做开源模型微调或蒸馏；否则大多数公司都是过早入场，根本没有足够推理量让省下的成本产生意义。

— Jeff Barg
31:47

给全世界 4000 万家公司打分，只要 1500 美元

Clay 自己的公司数据集有 4000 万家公司，每家公司的 LinkedIn 大约 1000 token，加上客户的理想客户画像（ICP）约 500 token，一次「这家公司适不适合我的产品」的判断就是 1500 token，按每十亿 token 42 美元算下来，把全世界每一家公司都筛一遍大约只要 1500 美元。他也给出获客成本参考：每条合格线索 1 到 10 美元是正常区间，预约一通电话的成本在 10 到 100 美元也不算离谱。

— Jeff Barg
34:55

用户恨模型选择器，但 Clay 不会删掉它

Jeff 直言「我们的用户讨厌模型选择器」，大多数客户看到选模型的界面会不高兴——他们只想把活干完，不想研究每个新模型的 eval 表现。Clay 即将上线一个「auto mode」路由，把模型选择交还给系统自己判断，理由是任务级别的路由比用户手动选更合理：找苹果 CEO 和找一家冷门小公司的 CEO，需要的模型强度完全不同。但他也承认，这等于让客户「相信我们把你的 token 花好了」，是一种信任机制而非透明机制。

— Jeff Barg
41:17

纽约招不到有生产级 agent 经验的人

Jeff 说 Clay 最难招的能力是「真正上手搭建过生产环境 agent」的人，这类经验在纽约比湾区更稀缺。背后的原因很朴素：ChatGPT 才出现四年，真正在 agent 工程上干满一年以上的人池子本来就小，这进一步限制了招聘范围，不只是地域问题。

— Jeff Barg
48:29

自家 agent 故意不做到比 Claude Code 更好

Clay 自建了 CLI、agent 沙箱，几乎所有能力都对齐了外部编码 agent，但 Jeff 明确说「我们刻意不想让自己的 agent 明显好过直接用 Clay 加 Claude Code」。团队测过自家 harness 和外部 harness（主要是 Claude Code）的使用占比，结果接近五五开，比预期更均衡。Clay 的定位是让自己成为「go-to-market 领域的 agent 基础设施」，不是去抢占入口，这也是它同时投入 CLI、MCP、API 多种形态的原因。

— Jeff Barg
55:50

OpenAI 临阵取消合作，三天后又反悔

Clay 是 ChatGPT apps 的首批商业应用合作方，为此抽调了约四分之一的工程团队连续冲刺一个月。发布前两天，OpenAI 突然通知要无限期推迟。Clay 判断这个赌注本身依然成立，选择继续按原计划开发，三四天后 OpenAI 真的改变主意，重新推进了合作。Jeff 用这件事说明「机构层面的勇气」——在变化极快的阶段，决策本身就会频繁反复，团队不能因为一次否定就放弃押注。

— Jeff Barg
1:10:54

模型还不会诊断自己的失败

Jeff 说即便到了现在，模型看一段很长的 agent trace，依然判断不出自己到底在哪里「卡壳」了——不是能力不够，而是直觉完全错误，常把正常的长耗时步骤当成问题本身。这导致 Clay 还在大量手写技能（skills）和规则，而不是让 agent 自我改进，这被他视为当前 agent 工程里最该被下一代模型解决、却还没解决的缺口。

— Jeff Barg
