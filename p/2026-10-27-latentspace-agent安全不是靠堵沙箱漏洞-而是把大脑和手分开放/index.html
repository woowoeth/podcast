Agent安全不是靠堵沙箱漏洞，而是把大脑和手分开放

Anthropic把执行代理架构拆成常驻服务器上的「大脑」和随时可销毁的沙箱「手」，凭证只存在出口网关，agent从未真正碰到过它们，这是意外但最关键的安全收益。

核心论点 · 点时间戳可跳到原声

1:01

人效一年涨了将近五倍

过去一年Anthropic的12个月收入/员工从140万美元涨到660万美元，同时从Q2每1美元收入要倒贴0.5美元，变成每1美元成本能赚2美元，本季度GAAP利润率19%，一年前是-129%。S1里把原因归为两个互相咬合的循环：更好的Claude带来更多用例和反馈，迭代出更强的Claude；收入增长带来更大投资，投资又喂养更强模型。

8:36

API 防蒸馏是场拉锯战

一篇公开论文证明可以从API里窃取推理链来蒸馏模型，促使团队加固了「保留思考块」「前缀锁定思考」等机制。团队强调这不是商业问题——蒸馏出去的模型如果绕开了安全分类器，才是他们真正担心的safety问题。为了不伤到正常用户，他们提前联系开源harness维护者和大客户，专门为被打断的压缩策略单独做了新的压缩功能替代。

21:47

一次事故逼出了一键断供的基础设施

每次发布模型都要单独定数据留存与审核政策——Opus 5.5就没有Fable那样的强留存要求。团队还搭了一套「信任凭证」系统，把「谁被授权用某个模型/项目」一路透传到系统底层。这套通用授权设施最初是Fable被紧急下线那次事故后，为了「万一还需要对所有人一键断供某个模型」而做的对冲投入，事后发现比预想中用得频繁得多。

54:01

CPU 跟 GPU 一样稀缺

多数人只盯着加速器层的算力紧张，但Anthropic发现CPU同样是瓶颈——产品服务、API、沙箱、CI全都在抢同一块CPU预算，而且跟训练用的沙箱算力是同一个零和游戏，靠云厂商谈下来的配额要在内部手动分配给所有业务线。过去可以按需在线扩容的CPU，现在也必须提前做容量规划。

56:19

零 Rust 经验的团队把 API 整体搬家

团队没有一个Rust工程师，却决定把整个Messages API从Python单体一次性port成Rust，而不是按部件分批迁移——因为具体代码由Claude来写，人只负责设计分布式系统架构、以及用影子流量验证新旧系统输出是否一致。结果CPU节省40%-50%，首token延迟改善10%-20%，团队因此多出了带宽去做更激进的、面向用户的架构改造。

1:03:49

大脑和手分开，安全是意外收获

Claude Managed Agent把常驻的harness（大脑）和随时可销毁的沙箱执行环境（手）分开，最初目的只是延迟和可靠性——沙箱挂了agent不会跟着死。唯独一位产品经理从一开始就坚持「这个架构最重要的属性其实是安全」，当时没人真信，团队成员后来说专门去跟这个人道歉。真正的安全收益是凭证从不进入agent可见的空间，只有出口代理在真正调用时才注入真实凭证。

1:11:19

减速发布和继续发新模型并不矛盾

发布会提到的「pacing」不等于不发新模型——Opus 5.5在上一代发布11天后就上线，只是因为它通过了架构安全、在线防护、离线分类三道关。但在线安全分类器制造了新的路由难题：一个普通用户只是问生物作业，对话里提到一次安全相关话题就可能被整段判定触发、降级到弱模型回答，而分类器本身没聪明到能把误判和真正的恶意区分开。

1:46:06

多智能体只需守住两条原则

对于多agent架构，建议只需满足两点：子agent之间共享统一上下文，并且彼此异步、不互相阻塞。满足这两条之后应该放手让Claude自己设计分工——他们预期未来Claude会自己学会拆分、克隆、调整协作架构，人只需要守住这两条约束，其余交给模型去试，可能会一次性解决过去觉得棘手的问题。
