飞书没被消灭，只是两个销售团队合并

艾瑞克从内部视角拆解：商业化团队并入火山引擎，本质上只是两个销售团队合并，因为面对同一波客户、同一笔预算，以前互相抢单，合并后提高效率；产品团队不是被豆包吞并，而是豆包企业版本来就不存在，它就是飞书里加了个豆包机器人，产品团队一直是从飞书借调过去的，现在只是汇报线回归谢欣；研发线没有任何变化。站在张一鸣角度，这是用组织调整解决内耗，而不是飞书「被消灭」。

— 艾瑞克
15:42

一只小龙虾把大厂规划从年压到按月

明浩给出两条时间线：一是头部厂商示范效应，OpenAI、Claude Code 等产品带来收入爆发；二是春节期间OpenCloud（小龙虾）在中国爆火，让巨头管理层第一次明确了「Agent应该长什么样」，形成了不犹豫的共识。原本按半年一年做的规划，现在压缩到按月算——去年Q4做的春节预案，今年3月就过时了。整个AI办公战场从立项到产品上线，只有两个季度不到的时间。

— 明浩
28:30

腾讯没有 to B 的牌，反而做出了赢家

明浩认为核心是腾讯没有to B的牌，所以最焦虑，才让边缘团队（应用宝、浏览器、腾讯会议背景）以极小团队做出Workbody。它本质是个人生产力工具，抓本地数据，没有企业数据壁垒，因此没有门槛，但恰好匹配了「个人为AI付费」的潮流。可信的日活数据是百万多，来自晚点报道中姚舜宇自己的表述。更重要的是，coding战场国内厂商被海外产品压着打，而办公场景（非编程人群）是增量，Workbody抓住了这个空白。

— 明浩
32:42

飞书嫌个人本地数据是别人不要的垃圾

艾瑞克认为，飞书手里有企业数据，智能问答和「开天眼」功能已经能把企业文档变成AI上下文——张一鸣不需要助理，直接在飞书里搜就能得到所有人的文档精华。因此飞书看不上个人版的本地数据工具，觉得那是「捡别人不要的垃圾」。但明浩反驳，这恰恰是大公司傲慢：飞书被并入豆包，说明张一鸣意识到不能把宝都押在豆包上，而个人生产力与企业办公的边界正在模糊，飞书押错了方向。

— 艾瑞克
49:54

不是谁击败谁，是飞书钉钉一起退场

明浩提出，飞书和钉钉打了五六年，最后不是谁击败谁，而是两人先后退出历史舞台——飞书进入豆包体系，钉钉之上又长出千问办公。狭义的企业IM历史使命已经完成，因为AI时代的人机协作不需要以IM为底座；但企业整套数字化AI是一个新议题，各家的状态各不相同。此前两家大厂的to B门面都没有跑出独立的商业结果，最终都成了集团AI大故事的拼图。

— 明浩
1:13:26

豆包三条变现路都不通，值钱的是用户画像

亚楠盘点豆包C端变现尝试：商品跳转GMV单量只有几万单，品牌广告（GEO）天花板几千万且伤害用户体验，C端付费渗透率低到「令人发指」。三条路都走不通，所以只能转向to B。但豆包有一个隐藏价值：它和抖音账号体系互通，用户画像质量远超抖音，能提升广告推荐精准度——字节去年国内外广告收入近900亿美金，哪怕提升1%就是10亿美金。这才是豆包作为资产的冰山以下部分。

— 亚楠
1:25:57

没人知道答案时，AB 测试只是浪费时间

讨论中提到，字节引以为傲的AB测试和中台机制在AI面前土崩瓦解：多团队协同、AB测试浪费时间，而AI变化太快，等协调完市场窗口已经过去。Workbody是单人小组快速做出来的，靠后期不断加人堆起来；字节则很多团队拼凑一个产品。当没有人知道正确答案时，多做尝试不如有信念地做一两个。甚至产品命名都带着路径依赖——「翠」这样的单字品牌，中文用户很难读准。

1:31:10

办公 Agent 只是把 coding 藏到界面后面

明浩总结：通用办公Agent只是把coding藏到了界面后面，生成网站、处理表格、修改文件背后都是工具调用能力，而coding是Agent的核心构成。过去半年到未来半年，coding是绝对共识，无论是模型的训练推理还是后训练，自主进化流程都建立在代码能力之上。这也解释了为什么头部厂商都把代码能力作为最核心的攻破点；另一派则主张世界模型路线，但短期内coding仍是基建。

— 明浩
