一次意外的快跑暴露了被压抑多年的运动天赋

Bryan 回忆 1993 年从科罗拉多返校时，为了不弄丢唯一一份 BattleTris 代码，徒手追上已经开动的机场摆渡车并追上了它。飞盘队队友目睹后震惊地问他是不是跑得很快，他才意识到自己大一到大二之间运动能力有了明显提升。这段故事解释了为什么这款游戏对他来说不只是代码，而是「生命的全部心血」的具体分量。

— Bryan Cantrill
25:40

复活老项目最难的不是技术，是看不到终点的不确定感

Adam 指出修复这种陈年项目的真正痛苦在于：你能看到每一步的增量进展，却不知道自己是离完成还有十五分钟还是六天。如果提前知道要花多久，人就会直接动手；但正是这种不确定性让人迟迟不敢开始去碰旧代码。

— Adam Leventhal
29:00

LLM 修的不是荣耀问题，而是当年的隐式假设

Bryan 强调横在复活旧软件和「完成」之间的，不是什么有趣的算法难题，而是几十年前写代码时做出的、现在早已不成立的隐式假设——这些问题修起来没有成就感，只是让软件恢复到它「本该已经做到」的样子。他们用 Theo Schlossnagle 讲过的 Stack Overflow 糊涂案例做类比：互联网上充满了别人复制根本不可能对自己管用的「fix」。

— Bryan Cantrill
40:30

Claude 独立找到了一个连作者自己都没想到的整数宽度 bug

两人对战时游戏在栈损坏后崩溃，Bryan 手头除了「发生了核爆交换」之外什么调试数据都没有，却直接把这个模糊描述丢给 Claude。Claude 找出了一个只有在 64 位系统下运行才会触发的整数宽度 bug——而 BattleTris 从写出来到现在从未以 64 位编译过。Bryan 形容这件事「genuinely wild」。

— Bryan Cantrill
47:50

LLM 让开源的许可证分叉焦虑可能被釜底抽薪

Bryan 把这次经历和 Cockroach、Terraform 等项目被「gaslight」成「社区不可能独立维护分叉版本」的案例联系起来，认为如果目标只是在旧版本里找 bug、修 bit rot，LLM 实实在在地改变了这个计算：原本担心要花一个月才能修好的隐式假设问题，现在变成了有界得多的工作量。

— Bryan Cantrill
50:50

Bun 用一次 PR 把整个代码库从 Zig 重写成 Rust

两人讨论了 Bun 项目的极端案例：有人直接用 LLM 把整个代码库从 Zig 重写为 Rust 并作为一个 PR 合并，里面还带着被社区认为明显不安全（unsound）的 unsafe 代码。Bryan 调侃说这下所有其他未合并的 PR 一夜之间语言都不对了，必须去解决巨量的 merge conflict。

— Bryan Cantrill
56:30

他们那条「AI 巨头将和教皇联名发白皮书」的预言成真了

Bryan 提到年初和 Adam、Simon Wilson 一起做的预测：AI 实验室会从「这东西要毁掉所有工作」转向「这东西造福全人类」的叙事，并类比烟草公司资助的医学研究，开玩笑说接下来会请奥巴马甚至教皇联名背书。结果这件事真的发生了，三人都觉得这个原本像段子的预测变成了现实。

— Bryan Cantrill
