AI 编程分水岭已至：DHH 从怀疑到狂喜

DHH 认为 Opus 4.5 是 AI 编程分水岭：agent 写的 PR 已超过中位数程序员，开发者正从写代码转向编辑与决策，过度指定反而会损害 agent 表现。

13:50

Opus 4.5 是分水岭

DHH 认为 2025 年 11 月 24 日发布的 Opus 4.5 是 AI 编程的分水岭。他回忆 26 日试用时，输出质量「惊人地接近」自己会写的代码，靠后惊叹「发生了什么」。他强调关键不仅是智能提升，更是 agent 工具链（如检查自身工作）的可用性，这彻底改变了工作方式。

— DHH
22:02

Basecamp 5 的教训

37signals 首个 agent 加速产品是 Basecamp 5。早期让设计师直接「vibe coding」导致大量 PR 破坏了系统架构，不得不人工清理。DHH 总结：在现有大型代码库上 vibe coding 需要程序员背景，否则架构会崩坏。但他反驳「vibe coder 是垃圾生成器」的指责，称普通程序员输出同样糟糕。

— DHH
1:02:41

过度指定会损害 agent

DHH 提到 Boris 在采访中说 Opus 5 的系统提示词缩小了 80%，因为 agent 不仅需要更少的人类指令，而且过度指定的指令反而会损害其表现。他类比点型老板对程序员指手画脚导致代码质量下降。他正在发展的技能是不过度指定，提供高层愿景和指导，让系统自行发挥。

— DHH
1:38:16

Agent 编程需并行处理

DHH 认为 agent 编程需要不同的工具集，核心变化是从单线程编程转向并行处理。因为 agent 既太快又太慢，不会像键盘输入那样即时回应，必须让 agent 运行一段时间，如果只等一个 agent，会感觉低效且无用。并行运行多个 agent 时，可以持续做决策、解阻塞、分配新任务，从而进入心流状态。

— DHH
2:35:00

模型排名与成本

DHH 给出当前模型排名：Fable 最佳，Opus 5 第二，但成本差异巨大。他用翻译 Python 库为 Rust 的任务测试了多个模型：Fable 45 分钟完成，成本 550 美元；Saul 1.5 小时，成本 40.6 美元；Grock 4.6 完成，成本 55 美元；DeepSeek 成本为 1/20；而 GPT Luna 和 Flash 失败。他总结 Fable 规划最强，但其他模型性价比更高。

— DHH
3:04:05

AI 驱动的开发循环

DHH 正在用 AI 构建一个管理 Omachi 开发的机器人系统，采用「大脑和手」模式：协调器运行模型，但操作一个安全的虚拟机，防止不可信代码污染模型。AI 主导了大部分设计决策，并能在循环中自我发现漏洞，例如识别测试响应中的恶意负载。这让他理解旧金山为何痴迷于「快速起飞」。

— DHH
3:15:16

生育率与未来希望

DHH 认为生育率下降削弱了人们对未来的投资意愿，导致虚无主义蔓延。他引用「种树」的比喻：如果孩子不会坐在树荫下，人们可能宁愿烧掉木材。他呼吁保持希望，并认为有后代是「skin in the game」，能激励人们为未来努力。

— DHH
