IDDQD 解决的是「同一个 key 存两份」的老问题

Oxide 用 CockroachDB 存大量记录，经常要按 UUID 之类的主键索引。Rust 标准 map 要求 key 和 value 分开存，于是团队要么把 key 复制一份存进 value（容易两边不同步），要么到处传元组（很不方便）。IDDQD 让用户直接存一整条记录，由用户定义如何从记录里提取 key，key 从 value 里「借」出来而不是复制。最早的版本靠 clone 实现（仍是安全 Rust），但对不能 clone 的「自然键」（由几个字段组合成的 key）不适用，于是 Rain 花了几周找到不需要 clone、靠 unsafe Rust 实现借用的方案。

— Rain Paharia
18:02

unsafe 不是关掉安全检查，是编译器能力的边界

Rain 提到 Rice 定理（等价于停机问题）：不存在一个终止的算法能完美判断任意程序是否有未定义行为。Rust 编译器选择「比完美更严格」——宁可拒绝一些实际上没问题的程序，也要保证安全 Rust 里绝不接受有未定义行为的程序。unsafe 就是给那些「你知道没问题，但编译器证明不了」的中间地带开的逃生舱，责任转移给了人。

— Rain Paharia
42:30

最难的 unsafe：正确性依赖于你无法信任的用户代码

IDDQD 的 unsafe 实现依赖用户实现的 hash、比较等 trait，而用户完全可以不守 Rust 规定的契约——比较函数可以随机翻转结果、同一个 key 两次哈希出不同值。Rain 说这时候得用「infosec 心态」而不是「软件工程心态」去想：攻击者（这里是写坏代码的用户）能怎么把你的假设打穿。关键原则是：用户代码写错，结果可以是跑出 bug，但绝不能让 Rust 的底层内存安全规则被打破。

— Rain Paharia
58:40

发现 bug 的导火索是围观 Bun 从 Zig 重写成 Rust

Rain 说真正促使他写这篇博客的，是自己在 IDDQD 里发现了一个真 bug，同时又在围观 Bun 项目被九天内用 AI 把一百万行代码从 Zig「转译」成 Rust、且早就停止接 PR。他认为这种转译本身可以接受，但代码里随手写的大量 unsafe 没有达到他认为的「对安全 Rust 用户负责任」的水准，这件事刺激他把「怎样才算负责任地写 unsafe Rust」写清楚。

— Rain Paharia
1:05:40

可变迭代器天生违反 Rust 规则，必须靠人工承诺

Rust 1.0 前定了一个设计：迭代器返回的值可以逃出 for 循环的作用域（比如 collect 成一个 vec），这意味着你可以同时拿到 map 里所有元素的可变引用。编译器没法证明这些引用彼此不重叠，所以实现 iter_mut 必须用 unsafe 手动向编译器「保证」这些值互不相同——而如果底层 map 被用户的错误代码骗得存了重复索引，这个保证就被打破，导致两个可变引用指向同一块内存。

— Rain Paharia
1:11:50

修复方案：抓到用户代码出错后，主动降级成低效但安全的扫描

Rain 发现可以用一个几乎总是对、但在特定点故意返回错误结果的 Ord 实现，诱骗 IDDQD 存入重复索引。修复分两步：一是用 tiebreaker 保证绝不会误匹配到错误的条目；二是一旦检测到用户代码已经不可信，remove 操作就从高效的索引查找降级成全程不调用用户代码的线性扫描——牺牲性能换取「哪怕用户代码坏了也绝不触发未定义行为」的保证。

— Rain Paharia
1:24:30

用 Claude Opus 4.7 和 GPT-5.5 当对抗性测试员找到了真 bug

Rain 把自己写的病态测试当种子，让 LLM 去尝试打破 map 的不变量。GPT-5.5 「嚼了大概二十分钟」之后找到了一种真正打破不变量的方法，Claude Opus 4.7 和它各自独立发现了一两处。这类用法之所以好用，是因为 LLM 找到的东西可以立刻用 Miri 这类解释器验证，不像「vibe coding」那样难以判断真假。

— Rain Paharia
1:30:10

Miri 分 stacked borrows 和 tree borrows 两套模型，IDDQD 卡在边界上

Miri 是解释 Rust 中间表示（MIR）的工具，用来判断某段 unsafe 代码是否违反别名规则。它有两种模型：较老、被公认过严的 stacked borrows，和试图放宽的 tree borrows。IDDQD 两种都要过 CI，但 Rain 不得不为了通过 stacked borrows 专门加了一些变通写法——说明这个库正好踩在两套规则分歧的边界上。

— Rain Paharia
