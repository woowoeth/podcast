1:01

先证明有人要，再谈能不能托付

面对「非技术创始人该在哪里收手不再 vibe coding」的问题，主理人给出的判断是顺序问题：在做出让别人依赖的产品之前，先验证别人真的想要它。很多情况下验证兴趣强度根本不需要一个能让人依赖的真实产品。即便现在可以做到可用的原型，真正的问题是「这个 App 不工作的下行有多严重」——是会死人，还是只是不方便。数据备份这类风险，很多第一次做的人根本想不到，但用 cloud code 或 codex 很容易设置好。他认为大多数情况下，vibe coding 就能做到第一批付费客户。

5:08

冷启动涨粉不靠回复，靠点赞

针对「客户不愿意推荐产品，因为怕引来更多竞争」的问题，主理人先质疑前提本身——预订营地这件事很难真的和别人撞期，所以这未必是真正的增长瓶颈。他给出一个具体的早期增长技巧：在 X 上，不需要回复别人的帖子（回复很容易显得 spammy，措辞也很难拿捏），只要点赞相关内容，别人就会点进你的主页看到你在做什么，这完全不 spammy，因为点赞本身就是真实兴趣的表达。

— Julian Weisser
8:12

新市场比抢存量市场更值得兴奋

对于「一个 2 万美元/月的高接触客户 vs 多个 1000 美元/月的自助客户」的选择，主理人提出的核心区分标准是：你是在替代一个已有的东西，还是在创造一个此前根本不存在的服务。他举了一个真实案例：一家公司把原本要花 40 万美元年薪才能做的工作，压缩到约 4 万美元就能完成，这让此前完全负担不起这项服务的大量企业第一次能够负担得起，从而打开了一个全新的客户群体。他也提醒，愿意付更多钱的客户往往是更好的客户，因为他们本就习惯花钱；但小客户那边可能没有内部人会因为采用新工具而感到被威胁。

— Julian Weisser
12:24

账户经理数量就是增长的瓶颈

回答「要不要为了招人而融资」时，主理人引用同一家公司的内部数据：他们对增长的唯一限制就是能招到多少客户对接/账户经理（account executive），每多招一个带来的价值都清清楚楚可量化。如果你处在这种「只差执行人手」的位置，融资故事就很清楚；但如果瓶颈在产品研发而非客户增长动能，情况就复杂得多。他还给出一个具体建议：有等待名单的话，直接让他们预付定金，既能覆盖招人成本，也能向投资人证明真实的客户拉力。

— Julian Weisser
15:30

要当董事长的天使投资人该被拒

匿名提问者遇到一个投资人，承诺能把公司送进顶级加速器、要求额外股权做导师并出任董事会主席。主理人直接判定这是红线：没有任何加速器会真的做出这种承诺，谁这么说谁就是骗子；更致命的是，公司甚至还没成立、只有一个创始人和一个原型，对方却想当董事长，这等于创始人在公司什么都没有之前就先交出了控制权。他对创始人的原话建议是「掉头就跑，别理这个人」，这位创始人最终确实拒绝了。

— Julian Weisser
17:36

拉线隐喻：别在局部最优里心满意足

对于「一个月换了三次方向、是在快速学习还是在逃避难点」的问题，主理人提出 Solo Founders 内部常用的比喻「pulling the thread（拉线）」：你可能正站在一个好主意的线头上，但如果不继续往下拉，就容易停在局部最优（local maxima）——有点东西在运转，让人兴奋或固执，但远没有达到本可能达到的全局高度。他还提出另一个概念「sitting in limbo（悬而不决）」：误以为每个方向决定都高度不可逆，结果花三周去做一个其实一周内就能逆转、也能带来新学习的决定，等于白白损失了那几周的学习机会。

— Julian Weisser
23:50

默认该融资，是创业者最糟的假设之一

对于「月入1.5万美元、自己一个人就能运营，但投资人在问能不能做成一亿美金公司」的提问，主理人指出现实更极端：现在大多数投资人其实在问能不能做成一千亿美金公司，这和创始人实际想要的东西常常是对立的。他认为默认应该融资是创业者能做的最糟糕的事情之一，真正该先搞清楚的是自己到底想不想做那种规模的公司，还是满足于现有收入、把钱存起来或投到别处，去过自己真正想要的生活——这两种选择都不丢人。

— Julian Weisser
