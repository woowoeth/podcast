程序員價值轉向調度 agent：DHH 用 AI 寫完整個產品

DHH 已用 AI 寫 Omachi 的全部代碼，並發現反直覺結論：agent 不需要囉嗦指令，需要並行運行；真正稀缺的是判斷、審美與架構約束。

AI 是數十年一遇的進步

DHH 對 AI 在編程中的角色只有興奮和樂觀，沒有存在性威脅。他引用列寧名言——「幾十年無事發生，幾週卻發生了幾十年的事」——說自己在過去九個月裡看到了數十年的進步。他把自己定位為親歷過互聯網和 AI 兩個時代轉換的人，認為這種經歷罕見且幸運。這段定調解釋了為什麼他後續所有判斷都建立在「變化真實發生」之上。

— DHH
13:50

Opus 4.5 是 AI 編程分水嶺

2025 年 11 月 24 日發布的 Opus 4.5 被他稱為 AI 編程的分水嶺。他回憶第一次使用時，輸出質量驚人地接近自己寫的代碼，讓他往後一靠、心想「發生了什麼」。他強調關鍵的提升不只是智能，而是可用性：AI 能使用工具、檢查自己的工作，因此能完成真正有意義的工作。這段為後文「AI 優於普通程序員」提供了直接證據。

— DHH
22:02

大代碼庫不能放開 vibe coding

Basecamp 5 是 37signals 首個真正由 AI 加速的產品，但早期讓設計師直接 vibe coding，導致大量 PR 破壞系統架構，最終不得不人工清理。DHH 的結論不是 AI 不可靠，而是：在現有大型代碼庫上，要保留架構完整性，必須有有經驗的程序員來引導 AI。對正準備把 AI 接入老代碼庫的團隊，這是一個具體的操作警示。

— DHH
31:43

只構建自己需要的 5%

DHH 分享自己用 AI 在 20 分鐘內用 C++ 和 Qt 寫了一個替代 Tapura 的寫作應用，兩天內就完全切換。他信奉「只構建自己需要的 5%」：AI 讓個人開發者能夠輕鬆創建定製化軟件，不必將就通用工具。他還建議把這類小工具發布到 GitHub，AI 會自動管理倉庫、寫 README、處理發布。這是「個人化軟件」從口號變成日常操作的具體樣本。

— DHH
1:02:41

過度指定會損害 agent

反直覺的發現：過度指定的指令反而損害 agent 的表現。DHH 以 Claude Code 的 Opus 5 為例，系統提示詞縮減了 80%，因為代理不再需要那麼多人類指令，甚至會被過度規定所傷害。他類比「尖頭髮老闆」——那些以為自己懂得更多、要求微觀管理的人，實際會拖累表現。正確做法是給 agent 足夠的模糊性，讓它自己探索最佳方案。這條直接挑戰「prompt 越詳細越好」的主流直覺。

— DHH
1:38:16

Agent 編程要從單線程轉向並行

Agent 編程需要不同的工具集，核心變化是從單線程轉向並行。手寫代碼時深度沉浸是心流；但 agent 既太快又太慢，需要等待，所以必須同時運行多個 agent。DHH 為此寫了 Herder——本質是 tmux 加 agent 通知，當 agent 完成或需要決策時響鈴。一個月前他覺得單機不夠快，買了多臺 Geekom 迷你電腦放進 closet，通過 Tailscale 組成虛擬局域網，目前能並行運行約 16 個線程。他從「保持心流」的角度證明：並行調度不是可選項，而是 agent 時代編程的必然形態。

— DHH
2:35:00

模型選型看速度、成本與能力

DHH 給出當下的模型選型判斷：最好的模型是 Fable，其次是 Opus 5，但差距不大。他用「把 Python 庫翻譯成 Rust」做實測：Fable 最快（45 分鐘）但成本 550 美元；Sonnet 和 Grok 4.6 成本低得多（約 40-55 美元）但耗時更長。結論是：不能只看「最強模型」，要按任務在速度、成本、能力之間取捨。他還轉述 Shopify CTO 的研究——agent 審查過的 PR 在生產中引發的問題更少。

— DHH
3:09:33

AI 首先淘汰「狗屁工作」

DHH 引用 David Graeber 的 Bullshit Jobs 研究：英國調查顯示約 30% 的工人認為自己的工作毫無價值。他堅持小公司、不拿 VC，原因之一就是懷疑大規模程序員協作的效率。他認為當前裁員潮更多是疫情時代過度招聘的後遺症，AI 只是藉口，但它確實會淘汰一些角色。他還借 F1 類比未來：數萬人做一件沒有內在價值的事，我們卻願意花數十億美元——AI 解放人類後，可能出現更多「輕浮」但真實的職業。

— DHH
