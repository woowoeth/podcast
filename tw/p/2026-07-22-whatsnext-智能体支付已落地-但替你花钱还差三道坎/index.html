Agent 購物的兩種場景

高寧與 Patrick 把 Agent Payment 拆成兩類。一類是用戶明確需求的電商購物、服務預訂，agent 幫執行，最終消費人還是人；另一類是 agent 在執行任務中自己產生的消費，比如調 API、買研報、下載資料，金額小但高頻，需要在授權額度內自主進行。前者體量大、鏈路長，後者是新增場景，目前主要發生在用戶與閉源模型（如 OpenAI、Claude）的對話裡。

— 高寧

三道關卡：信任、授權、商戶就緒

Patrick 認為當前最大問題不是技術，而是三個環節。第一，agent 的智力與推薦質量還沒贏得用戶信任，上下文懂你不代表懂你喜歡；第二，agent 不能被信任保管卡信息，一旦發生倒刷，責任要用戶自己承擔；第三，商戶端對 agent 下單帶來的客戶關係歸屬有疑慮，且 agent 在普通用戶中滲透率低，商家大規模投入的 ROI 不足，導致 merchant readiness 進展緩慢。

— Patrick
9:48

Clink × Visa VIC 第一筆交易

Patrick 介紹與 Visa 的合作：Clink 被定位為 Visa 全球生產網中的第一個 agent enableer。6 月底在博覽會上執行了 VIC 的第一筆交易。流程是 agent 把用戶上下文、授權額度和商品類型傳給 Clink，Clink 記錄為 mandate；agent 找到商品後，Clink 校驗與原始授權是否一致，再向 Visa 申請一次性支付能力，Visa 核驗後完成支付。這套機制把最終追責鏈路變得清楚。

— Patrick
12:57

法幣優於穩定幣的原因

Patrick 解釋 Clink 選擇法幣而非穩定幣的原因：法幣體系中的消費者保護機制成熟，銀行和卡組織對授權、爭議處理都有完整流程，信任問題更容易解決；而穩定幣一旦支付出去基本不可逆，消費者信心和持續信任都會受損。隨後嘉賓補充了一個真實案例：有公司解僱員工後某個 token 一夜燒掉 600 多美元，無法追查，後來只能改為每人單獨 API 以便追溯。

— Patrick
16:04

穩定幣在做鏈上支付寶

高寧介紹穩定幣賽道的進展。穩定幣體系裡，單純的小額轉賬已經比較成熟，因為鏈上支付就是端到端轉賬。更有意思的是有人在嘗試解決淘寶早期的問題：用戶和商家互不信任。方案是用智能合約把錢鎖在中立位置，確認交付後再釋放給商家，解決「錢付了不發貨」的不可逆問題。高寧認為小額高頻的基礎設施已不缺，缺的是場景豐富度和用戶習慣的遷移。

— 高寧
23:24

Clink 是高速公路之間的匝道

Patrick 說 Clink 不是新修一條高速公路，而是去做路與路之間的匝道。用戶可能從 OpenAI 的 ACP 協議來，商戶卻用的是 Shopify 或 Stripe；不同協議、不同支付公司、不同電商平臺之間需要有人做轉換和銜接。Clink 的策略是儘量兼容 UCP、ACP，並給 Shopify、Magento 等電商平臺做插件，讓商戶低成本 onboarding，在現有 OMS 和訂單體系不變的情況下變成 agent payment ready。

— Patrick
29:30

中國支付生態的獨特路徑

高寧說國內沒有海外卡組織的倒刷/申訴體系，更多是客訴性質，責任歸屬不同。但國內電子支付普及率極高、基建成熟，只是時間問題。騰訊在做 Agent 卡，支付寶公布了 AMP 協議，但場景落地還沒看到。主持人補充說微信 Agent 生態可能幾個月內發布，正在和幾個大商家跑，說不定第一個大規模 agent payment 會先發生在中國。

— 高寧

未來一年想看到的信號

Patrick 說兩個信號：一是真的有用戶因為 agent 找到了自己沒想到的好東西，出現 aha moment，突破推薦算法「too well」的信息繭房；二是越來越多人開始調用付費的外部數字服務，而不是只用 token 本身。高寧則有個更個人的期待：他一直在用 GPT 聊自己的腸胃炎症狀並得到益生菌推薦，但最後還得自己再去別的平臺下單、開處方，他希望這個流程直接從對話變成下單、寄到家裡，而且他判斷國內會更快。

術語

Agent Payment智能體支付
由 AI 智能體代替人類發起並完成的支付。
ACPAgent 商業協議
OpenAI 提出的智能體交易協議，讓 agent 在授權範圍內完成購買。
UCPUser Choice Protocol
Google 提出的智能體支付協議，強調用戶對交易的選擇權。

agent enableer智能體使能者
幫助 agent 接入現有支付體系的中間角色。
