GTM engineer 是從「堆人」到「寫系統」的轉變

Jeff Barg 解釋 go-to-market engineer 這個稱呼的來源：2010 年代公司靠堆更多銷售和市場人員來找客戶，但 LLM 出現後，agent 可以自己去爬網、給客戶打分、執行判斷，於是出現了一批用軟件工程方法做增長的人——寫 prompt、做數據工程、搭自動化系統。這個角色融合了 agent 工程、數據工程和傳統軟件工程，此前這類工作大多落在 revenue operations 部門裡，沒有獨立身份。

— Jeff Barg
25:34

沒有 CRM 數據，agent 就是瞎子

Sculptor 第一版最大的短板不是模型能力，而是缺上下文：agent 拿不到 CRM 數據，也看不到一封 outbound 郵件發出去之後的真實結果，導致它沒法像真正的銷售代表那樣做判斷。團隊為此重建了整個平臺的數據層（Audiences），把 CRM、Gong 通話記錄等第一方數據和 Clay 自帶的公司數據集做實體對齊，變成一張「權威的客戶與聯繫人大表」，agent 才有東西可用。

— Jeff Barg
29:45

post-training 只有在推理花費到千萬級才划算

Jeff 說 Clay 過去 18 個月一直覺得自己訓模型不現實，直到最近才開始考慮。他給出一個經驗門檻：只有當推理花費達到大約 1000 萬到 1 億美元規模時，省下來的錢才「夠重」（chunky），值得去做開源模型微調或蒸餾；否則大多數公司都是過早入場，根本沒有足夠推理量讓省下的成本產生意義。

— Jeff Barg
31:47

給全世界 4000 萬家公司打分，只要 1500 美元

Clay 自己的公司數據集有 4000 萬家公司，每家公司的 LinkedIn 大約 1000 token，加上客戶的理想客戶畫像（ICP）約 500 token，一次「這家公司適不適合我的產品」的判斷就是 1500 token，按每十億 token 42 美元算下來，把全世界每一家公司都篩一遍大約只要 1500 美元。他也給出獲客成本參考：每條合格線索 1 到 10 美元是正常區間，預約一通電話的成本在 10 到 100 美元也不算離譜。

— Jeff Barg
34:55

用戶恨模型選擇器，但 Clay 不會刪掉它

Jeff 直言「我們的用戶討厭模型選擇器」，大多數客戶看到選模型的界面會不高興——他們只想把活幹完，不想研究每個新模型的 eval 表現。Clay 即將上線一個「auto mode」路由，把模型選擇交還給系統自己判斷，理由是任務級別的路由比用戶手動選更合理：找蘋果 CEO 和找一家冷門小公司的 CEO，需要的模型強度完全不同。但他也承認，這等於讓客戶「相信我們把你的 token 花好了」，是一種信任機制而非透明機制。

— Jeff Barg
41:17

紐約招不到有生產級 agent 經驗的人

Jeff 說 Clay 最難招的能力是「真正上手搭建過生產環境 agent」的人，這類經驗在紐約比灣區更稀缺。背後的原因很樸素：ChatGPT 才出現四年，真正在 agent 工程上幹滿一年以上的人池子本來就小，這進一步限制了招聘範圍，不只是地域問題。

— Jeff Barg
48:29

自家 agent 故意不做到比 Claude Code 更好

Clay 自建了 CLI、agent 沙箱，幾乎所有能力都對齊了外部編碼 agent，但 Jeff 明確說「我們刻意不想讓自己的 agent 明顯好過直接用 Clay 加 Claude Code」。團隊測過自家 harness 和外部 harness（主要是 Claude Code）的使用佔比，結果接近五五開，比預期更均衡。Clay 的定位是讓自己成為「go-to-market 領域的 agent 基礎設施」，不是去搶佔入口，這也是它同時投入 CLI、MCP、API 多種形態的原因。

— Jeff Barg
55:50

OpenAI 臨陣取消合作，三天後又反悔

Clay 是 ChatGPT apps 的首批商業應用合作方，為此抽調了約四分之一的工程團隊連續衝刺一個月。發布前兩天，OpenAI 突然通知要無限期推遲。Clay 判斷這個賭注本身依然成立，選擇繼續按原計劃開發，三四天後 OpenAI 真的改變主意，重新推進了合作。Jeff 用這件事說明「機構層面的勇氣」——在變化極快的階段，決策本身就會頻繁反覆，團隊不能因為一次否定就放棄押注。

— Jeff Barg
1:10:54

模型還不會診斷自己的失敗

Jeff 說即便到了現在，模型看一段很長的 agent trace，依然判斷不出自己到底在哪裡「卡殼」了——不是能力不夠，而是直覺完全錯誤，常把正常的長耗時步驟當成問題本身。這導致 Clay 還在大量手寫技能（skills）和規則，而不是讓 agent 自我改進，這被他視為當前 agent 工程裡最該被下一代模型解決、卻還沒解決的缺口。

— Jeff Barg
