Anthropic五個月將核心API從Python重寫成Rust，沒人逐行審查代碼

驗證靠的不是讀代碼，而是讓新舊系統跑影子流量比對輸出；同一套思路後來被用在把CPU佔用砍到三分之一的Agent架構重建上。

10:07

CPU不再是能隨便加購的資源

Anthropic最早的API是研究團隊為了方便和模型、研究代碼互通而選的Python單體服務，只跑在單個GCP區域。隨著請求量暴漲——尤其是今年投放超級碗廣告後出現的流量尖峰——這套單體服務開始撐不住CPU需求。Caitlyn說這是她職業生涯裡第一次感到「哪怕願意付錢，雲廠商也給不出你想要的CPU量」，這倒逼團隊放棄靠加機器橫向擴容的老辦法，開始考慮用更底層的語言重寫整個API層。

— Caitlyn
22:13

驗證靠影子流量比對，不靠人讀代碼

因為數據隱私，團隊看不到用戶的原始請求內容，無法直接debug Python和Rust兩套系統的輸出差異。他們的辦法是搭一個極薄的Python前門，把請求同時shadow到Rust系統，先確保進入推理前的處理結果一致，再在返回時核對token計數，日復一日把兩套系統的差異率壓到接近於零，最後才拆掉前門。Caitlyn說團隊估計約80%由agent提交的PR，沒有被人逐行深讀過。

— Caitlyn
44:47

第一版Managed Agents能用，團隊卻選擇推倒重來

第一版直接在sandbox裡啟動Cloud Code，撞上四個問題：sandbox掛了agent就死、啟動延遲高、模型憑證和agent被塞進同一個sandbox不安全、每個會話都要佔滿CPU。團隊沒有逐個打補丁，而是從第一性原理重新設計：harness跑在持久服務器上，只在需要執行時才臨時拉起sandbox，憑證放進獨立vault、在請求出口才注入。結果新架構CPU佔用降到原來的約三分之一，Caitlyn承認當時「決定推倒重來確實是個重大決定」，但因為實現成本大幅降低，這種選擇比過去容易接受得多。

— Caitlyn
59:14

機械式改動可以繞過人類審核直接上線

像SDK版本號升級這類高度重複、結果可預測的變更，Anthropic訓練了一個分類agent先判斷這是不是「機械式變更」：如果是，就由另一個Claude審查後直接合並部署，不需要人去看；只有被判定有風險的變更才會升級給人類。團隊的明確目標是持續擴大這個可以無人值守通過的變更範圍，而不是停在現有比例上。

— Caitlyn
1:06:28

報警先交給Claude過濾噪音

API的on-call輪值讓Claude先接收所有報警，第一步只做一件事：判斷這是噪音還是真實問題。如果是噪音就不打擾人；如果是真實問題，Claude一邊把報警升級給值班工程師，一邊自己開始診斷，等工程師真正打開電腦時，往往已經有了診斷結果和修復建議。Caitlyn強調目前還沒做到讓Claude獨立處理真實故障，但光是「判斷是不是噪音」這一層，就已經省下了大量人力和被叫醒的次數。

— Caitlyn
1:09:33

產品經理也能把代碼推上生產環境

developer console裡的prompt caching診斷功能，整個實現是一個產品經理和Claude在Slack裡來回對話做出來的，工程師只負責審查代碼質量。Caitlyn說「誰可以直接推生產」這條線正在不斷後移，但系統最終出問題時，被叫起來負責的仍然是擁有該系統的工程團隊，而不是寫代碼的產品經理——問責主體沒變，變的只是誰能動手寫代碼的門檻。

— Caitlyn
1:23:56

算法編程面試被淘汰，但替代方案還沒定型

Anthropic發現候選人經常在傳統coding interview裡考砸，卻能在系統設計、項目經歷等其他面試環節表現很好——原因很簡單，他們已經很久不手寫代碼了。公司沒有直接刪掉這道面試，而是在試驗一批「以agent為中心」的新題型：審查agent寫的代碼、評估agent做的系統設計、用coding agent完成一個具體任務，試圖找到真正能測出「會不會用工具把事情做成」的方法。

— Caitlyn
1:33:13

身份焦慮的解法是把野心調高，而不是躺平

Caitlyn認為工程師的身份危機，根源是過去的自我認同建立在「手敲代碼」上。她的建議是：要讓大規模多agent系統去解決治病、新藥審批這類真正宏大的問題，前提是先有人把security、auth、infra這些底層工程問題解決好，否則一大群agent解決不了好問題，只會先一起捅出大簍子。她同時提醒，哪怕只有Claude Max套餐、沒有frontier lab級別預算的工程師，也應該持續把自己負責的系統的野心調高，而不是因為「agent遲早能做」就停下來。

— Caitlyn

If you were to ask the team, they would probably say something like 80% of the pull requests that got opened by agents, they didn't like Deeply read through all of the code that had gotten written. And then I would say like 20 % probably is where you were running into issues.

如果你去問團隊，他們大概會說，agent打開的那些pull request裡，大概80%他們並沒有深入讀過所有寫出來的代碼。剩下大概20%，才是真正需要去深挖細節、解決問題的地方。

we found ourselves running on average around a third of the CPU for this system as the original system. And so we threw the whole thing out and we rebuilt it.

the goal is to get to a point where when a page comes in and we're just starting to do this, when a page comes in, it goes to that cloud first. And that cloud can decide, is this noise or is this real? And that's just the first gate.

我們的目標是——我們才剛開始做這件事——當一個報警進來時，先交給那個Claude處理，由它判斷這是噪音還是真實問題。這只是第一道關卡。

someone might not pass that coding interview, but they would like crush all the rest of the interviews. And it's because they're not writing code by hand all the time anymore, right?

有人可能過不了那種編程面試，但在其餘所有面試環節都表現得非常出色。原因就是他們已經不再總是手寫代碼了。

this is for the engineers feeling an identity crisis because they think their knowledge and skills won't be important, even though your skills can be the difference in whether or not these complex problems will be tackled.

這是寫給那些感到身份危機的工程師的——他們覺得自己的知識和技能不再重要，但其實你的技能恰恰可能決定這些複雜問題最終能不能被解決。
