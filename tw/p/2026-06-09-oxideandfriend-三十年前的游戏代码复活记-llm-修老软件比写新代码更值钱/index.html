三十年前的遊戲代碼復活記：LLM 修老軟件比寫新代碼更值錢

兩個老程序員用 Claude 復活了一款 1993 年寫的對戰版俄羅斯方塊，過程中 LLM 修好了連 32 位轉 64 位都沒出現過的整數寬度 bug，診斷鏈條清晰到讓人意外。

一次意外的快跑暴露了被壓抑多年的運動天賦

Bryan 回憶 1993 年從科羅拉多返校時，為了不弄丟唯一一份 BattleTris 代碼，徒手追上已經開動的機場擺渡車並追上了它。飛盤隊隊友目睹後震驚地問他是不是跑得很快，他才意識到自己大一到大二之間運動能力有了明顯提升。這段故事解釋了為什麼這款遊戲對他來說不只是代碼，而是「生命的全部心血」的具體分量。

— Bryan Cantrill
25:40

復活老項目最難的不是技術，是看不到終點的不確定感

Adam 指出修復這種陳年項目的真正痛苦在於：你能看到每一步的增量進展，卻不知道自己是離完成還有十五分鐘還是六天。如果提前知道要花多久，人就會直接動手；但正是這種不確定性讓人遲遲不敢開始去碰舊代碼。

— Adam Leventhal
29:00

LLM 修的不是榮耀問題，而是當年的隱式假設

Bryan 強調橫在復活舊軟件和「完成」之間的，不是什麼有趣的算法難題，而是幾十年前寫代碼時做出的、現在早已不成立的隱式假設——這些問題修起來沒有成就感，只是讓軟件恢復到它「本該已經做到」的樣子。他們用 Theo Schlossnagle 講過的 Stack Overflow 糊塗案例做類比：互聯網上充滿了別人複製根本不可能對自己管用的「fix」。

— Bryan Cantrill
40:30

Claude 獨立找到了一個連作者自己都沒想到的整數寬度 bug

兩人對戰時遊戲在棧損壞後崩潰，Bryan 手頭除了「發生了核爆交換」之外什麼調試數據都沒有，卻直接把這個模糊描述丟給 Claude。Claude 找出了一個只有在 64 位系統下運行才會觸發的整數寬度 bug——而 BattleTris 從寫出來到現在從未以 64 位編譯過。Bryan 形容這件事「genuinely wild」。

— Bryan Cantrill
47:50

LLM 讓開源的許可證分叉焦慮可能被釜底抽薪

Bryan 把這次經歷和 Cockroach、Terraform 等項目被「gaslight」成「社區不可能獨立維護分叉版本」的案例聯繫起來，認為如果目標只是在舊版本里找 bug、修 bit rot，LLM 實實在在地改變了這個計算：原本擔心要花一個月才能修好的隱式假設問題，現在變成了有界得多的工作量。

— Bryan Cantrill
50:50

Bun 用一次 PR 把整個代碼庫從 Zig 重寫成 Rust

兩人討論了 Bun 項目的極端案例：有人直接用 LLM 把整個代碼庫從 Zig 重寫為 Rust 並作為一個 PR 合併，裡面還帶著被社區認為明顯不安全（unsound）的 unsafe 代碼。Bryan 調侃說這下所有其他未合併的 PR 一夜之間語言都不對了，必須去解決巨量的 merge conflict。

— Bryan Cantrill
56:30

他們那條「AI 巨頭將和教皇聯名發白皮書」的預言成真了

Bryan 提到年初和 Adam、Simon Wilson 一起做的預測：AI 實驗室會從「這東西要毀掉所有工作」轉向「這東西造福全人類」的敘事，並類比菸草公司資助的醫學研究，開玩笑說接下來會請奧巴馬甚至教皇聯名背書。結果這件事真的發生了，三人都覺得這個原本像段子的預測變成了現實。

— Bryan Cantrill
