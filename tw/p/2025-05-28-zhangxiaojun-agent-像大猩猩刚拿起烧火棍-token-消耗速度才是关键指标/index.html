續航數據和續航體驗不劃等號

明超平在 OnePlus 做產品時發現，紙面續航數據最漂亮，用戶反饋卻不好。原因是用戶只在兩個區間對電量敏感：95%-100% 拔下手機那一刻，以及 5%-0% 最焦慮的時候。蘋果最後 5% 電量特別耐用，是因為那不是真實數據上的 5%，可能是 10%，用足夠多的電量緩解焦慮。很多公司把續航設計成線性直線，理想狀態應該是 S 型曲線。體驗是主客觀一塊的，不是純數據導向。

— 明超平
37:42

字節方法論會磨滅靈光一現的創意

明超平認為字節的數據驅動體系在拉高整體平均水平，讓剛進來的校招生一星期交出 80 分結果，因為 AB 實驗已經附下了 20%，你再怎麼蠢也不會把它上線。但它抹滅的是最頂級的 100 分天才的靈光一現創意——iPhone 的多點觸控屏、特斯拉，這些顛覆式創新都驗證不出來。他把數據比作開車的後視鏡：可以看到過去走過的路，但沒法指引你往前開。

— 明超平
1:13:18

token 消耗速度才是 AI 時代的關鍵指標

2025 年春節後，明超平失眠時問自己：假如我是 VC 看 AI 產品，應該看什麼？DAU 是從移動互聯網時代來的，今天不一定還是關鍵指標。他得到的結論是看 token 的消耗速度。後來看到 Manus 的訪談，發現不謀而合。但他今天又迭代了：消耗越大不一定越好，更往前推一步是追求每個 token 的價值，叫 per token valuation。比如用一百萬 token 寫個網站，可能很多 token 是浪費的，好的 agent 應該用更少 token 寫出網站。

— 明超平
1:16:33

殼被低估了，應該叫容器和環境

明超平認為殼這個詞被大家低估了，他更願意叫容器和環境。環境是人的反應器——同樣一個人，去大排檔吃燒烤和去高檔法式餐廳，行為、說話方式甚至聲音都會不一樣。只給用戶一個 prompt 框是不負責任的，因為用戶真的不知道拿這個產品幹什麼。Midjourney 早期用戶輸的就是 a dog、a cat 這種短句，今天 500 個詞的 prompt 是在 discord 頻道里演化出來的，用戶看到別人的作品、複製別人的 prompt、再二創，這個過程交換了所有人怎麼用這個產品。

— 明超平
1:21:18

Coding 發展和當年 Camera 類似

明超平把 coding 的技術發展比作手機 camera 的發展。早期聊相機是拿著單反、調 ISO 調快門速度的人，但手機上出現 camera 後，出現了一幫新的人群叫手機攝影師。今天 coding 也一樣，以前不會編程就無法 coding，今天 web coder 自然語言編程出現了。第二個變量是增速非常快，當年手機 camera 出現後一天產生的照片量級從 100 萬張到 1000 萬張到 1 億張，指數級上升。趨勢變量早期都是一幫新的人群出現，並且增速非常快。

— 明超平
1:36:13

Agent 生態像新加坡和美國兩種國家

明超平用國家比喻 agent 生態：一種是非常獨裁專制的國家，運行效率極高但強人政治；一種是民主制國家，共和黨民主黨來回 battle，修條鐵路可能修二十年。背後是兩種理念——追求上限和保住下限。對應到 agent，一種是一個 agent 調度所有其他垂直 agent，另一種是一堆垂直 agent 來回調度。他更傾向於後者，因為如果把 PageRank 變成 agent rank，最大的問題是把所有 2C 公司都變成 2B 公司，會受到反抗。

— 明超平
1:53:17

下一個 OS 應該是活的，界面實時生成

明超平認為今天操作系統的所有界面是固定好的死的，是程序員提前寫好的，每個流程都是點個按鈕就跳那個界面。但下一個 OS 應該是活的，所有界面是實時生成出來的，基於你當時的任務場景。比如開車時那塊屏展示什麼，和電腦上不一樣，甚至開車開的時候和停的時候長得不一樣。開會時為什麼不會實時生成一個界面，既可以看到字幕，也可以記筆記，還可以看到進展。這需要一套 coding 引擎，未來打開網站的兩秒鐘裡除了數據傳輸，還有界面實時渲染生成。

— 明超平
2:33:44

創業像下圍棋，重要的是下棋順序

明超平把創業比作下圍棋，圍棋裡有個東西叫打譜，一盤棋下完之後復盤，把棋譜擺在面前分析。他強調重要的不是最終的棋譜長什麼樣，而是它下棋的順序。不能今天看到抖音長這個樣子、微信長這樣子，就做一個一模一樣的東西出來，因為那第五十步如果你下錯了，可能就沒有第一百步了。做產品優先級就是順序的一種重要體現：什麼東西做，什麼東西不做，什麼東西能三年後做，什麼東西今天必須做。

— 明超平
