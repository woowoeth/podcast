飛書沒被消滅，只是兩個銷售團隊合併

艾瑞克從內部視角拆解：商業化團隊併入火山引擎，本質上只是兩個銷售團隊合併，因為面對同一波客戶、同一筆預算，以前互相搶單，合併後提高效率；產品團隊不是被豆包吞併，而是豆包企業版本來就不存在，它就是飛書里加了個豆包機器人，產品團隊一直是從飛書借調過去的，現在只是彙報線迴歸謝欣；研發線沒有任何變化。站在張一鳴角度，這是用組織調整解決內耗，而不是飛書「被消滅」。

15:42

一隻小龍蝦把大廠規劃從年壓到按月

明浩給出兩條時間線：一是頭部廠商示範效應，OpenAI、Claude Code 等產品帶來收入爆發；二是春節期間OpenCloud（小龍蝦）在中國爆火，讓巨頭管理層第一次明確了「Agent應該長什麼樣」，形成了不猶豫的共識。原本按半年一年做的規劃，現在壓縮到按月算——去年Q4做的春節預案，今年3月就過時了。整個AI辦公戰場從立項到產品上線，只有兩個季度不到的時間。

— 明浩
28:30

騰訊沒有 to B 的牌，反而做出了贏家

明浩認為核心是騰訊沒有to B的牌，所以最焦慮，才讓邊緣團隊（應用寶、瀏覽器、騰訊會議背景）以極小團隊做出Workbody。它本質是個人生產力工具，抓本地數據，沒有企業數據壁壘，因此沒有門檻，但恰好匹配了「個人為AI付費」的潮流。可信的日活數據是百萬多，來自晚點報道中姚舜宇自己的表述。更重要的是，coding戰場國內廠商被海外產品壓著打，而辦公場景（非編程人群）是增量，Workbody抓住了這個空白。

— 明浩
32:42

飛書嫌個人本地數據是別人不要的垃圾

艾瑞克認為，飛書手裡有企業數據，智能問答和「開天眼」功能已經能把企業文檔變成AI上下文——張一鳴不需要助理，直接在飛書裡搜就能得到所有人的文檔精華。因此飛書看不上個人版的本地數據工具，覺得那是「撿別人不要的垃圾」。但明浩反駁，這恰恰是大公司傲慢：飛書被併入豆包，說明張一鳴意識到不能把寶都押在豆包上，而個人生產力與企業辦公的邊界正在模糊，飛書押錯了方向。

— 艾瑞克
49:54

不是誰擊敗誰，是飛書釘釘一起退場

明浩提出，飛書和釘釘打了五六年，最後不是誰擊敗誰，而是兩人先後退出歷史舞臺——飛書進入豆包體系，釘釘之上又長出千問辦公。狹義的企業IM歷史使命已經完成，因為AI時代的人機協作不需要以IM為底座；但企業整套數字化AI是一個新議題，各家的狀態各不相同。此前兩家大廠的to B門面都沒有跑出獨立的商業結果，最終都成了集團AI大故事的拼圖。

— 明浩
1:13:26

豆包三條變現路都不通，值錢的是用戶畫像

亞楠盤點豆包C端變現嘗試：商品跳轉GMV單量只有幾萬單，品牌廣告（GEO）天花板幾千萬且傷害用戶體驗，C端付費滲透率低到「令人發指」。三條路都走不通，所以只能轉向to B。但豆包有一個隱藏價值：它和抖音賬號體系互通，用戶畫像質量遠超抖音，能提升廣告推薦精準度——字節去年國內外廣告收入近900億美金，哪怕提升1%就是10億美金。這才是豆包作為資產的冰山以下部分。

— 亞楠
1:25:57

沒人知道答案時，AB 測試只是浪費時間

討論中提到，字節引以為傲的AB測試和中臺機制在AI面前土崩瓦解：多團隊協同、AB測試浪費時間，而AI變化太快，等協調完市場窗口已經過去。Workbody是單人小組快速做出來的，靠後期不斷加人堆起來；字節則很多團隊拼湊一個產品。當沒有人知道正確答案時，多做嘗試不如有信念地做一兩個。甚至產品命名都帶著路徑依賴——「翠」這樣的單字品牌，中文用戶很難讀準。

1:31:10

辦公 Agent 只是把 coding 藏到界面後面

明浩總結：通用辦公Agent只是把coding藏到了界面後面，生成網站、處理表格、修改文件背後都是工具調用能力，而coding是Agent的核心構成。過去半年到未來半年，coding是絕對共識，無論是模型的訓練推理還是後訓練，自主進化流程都建立在代碼能力之上。這也解釋了為什麼頭部廠商都把代碼能力作為最核心的攻破點；另一派則主張世界模型路線，但短期內coding仍是基建。

— 明浩
