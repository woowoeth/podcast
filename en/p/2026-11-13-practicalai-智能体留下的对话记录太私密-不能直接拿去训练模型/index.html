Agent conversations are too private to directly use for training

Agent execution traces hold user prompts, medical records, file content—data far harder to openly collect than phone photos. Federated learning becomes the natural choice for improving agents without moving data.

The core of federated learning is not encryption, it's data that doesn't move

Lorenzo explains federated learning's basic logic: valuable data scattered across edge devices like phones and laptops can't be centrally collected due to privacy and compliance concerns—medical records, for instance. Federated learning moves the training process itself to where data lives, rather than moving data to a data center. This resolves the tension between "meeting privacy regulations" and "learning from the data"—the reason the framework exists.

— Lorenzo
8:10

Data staying local doesn't mean the model forgot secrets

On how privacy is actually protected, Lorenzo breaks it down in layers: first, data never physically leaves its source—no one can intercept or read it. But the second-layer problem is whether the trained model itself "memorized" what it shouldn't. That's where privacy truly breaks down. Differential privacy and similar techniques provide statistical-level guarantees, though applicability varies by scenario—some scenarios suit them, others don't. Many industries will eventually drop federated learning because it's uneconomical.

— Lorenzo
11:40

Privacy-sensitive applications should start with open-source models

Asked whether closed-source or open-source models deserve more trust, Lorenzo admits nobody really knows how closed-source models are constructed, and he personally assumes companies try hard to protect privacy. But for truly privacy-sensitive work, he'd begin with open-source models, since they're far more inspectable and fixable. Once a closed-source model fails, you nearly can't guarantee a complete fix.

— Lorenzo
16:40

Agent trajectories are far more sensitive than isolated conversations

Unlike a single model's question-answer exchange, an agent system's trajectory includes not just model outputs but also the user's raw prompts and context supplied by third-party components like MCP servers and RAG systems. These trajectories are invaluable for improving agents, as models often stumble in long sequences due to typos, word sense ambiguity, or tool flaws—better training needs enough trajectory data. Yet trajectories mix in private matters like whether a sore knee warrants a doctor visit, exactly where federated learning steps in.

— Lorenzo
19:50

Each step an agent takes exposes another layer of yourself

Discussing agent versus single-model differences, Lorenzo emphasizes the key: agents "take action"—read, fetch, modify, delete. Each execution happens in an environment containing user pieces—notebook data, physical systems, camera streams. As long-running traces grow, the information an agent holds about the user accumulates steadily, since producing a final result requires absorbing more data. The process branches like a tree from the main path into sub-agent calls, then collapses back to the main line for the final answer.

— Lorenzo
32:30

Models grow smaller, but enterprises grip training data tighter

Lorenzo spots a trend: the strongest models are becoming tinier, cheaper, simpler to deploy, but making models better for specific use cases demands deep failure-mode analysis, only possible when enterprises fully own their trajectory data. Many companies deploy models and find them hard to improve—the root issue is they can't review trajectories and spot where the model misfired. He forecasts large enterprises will increasingly hold their trajectory data and self-improve models, since this data is core IP anyway, and outside vendors typically won't reveal the full path the model took to reach its answer.

— Lorenzo
37:10

Robot surgeons cut, and nobody knows their reasoning

Lorenzo recalls seeing a model guide a robot through actual surgery, triggering a deeper question: do we know why the model chose that particular step, can we confirm it weighed all alternatives first. In high-stakes domains like surgery, people urgently need to understand the reasoning behind workflow choices—exactly why the interpretability research path matters increasingly, and why enterprises need much deeper data control and analysis power than standard subscription services grant.

— Lorenzo
39:40

Surgery can't be simulated at scale, so hospitals must pool data

On surgical robots and similar cases, Lorenzo notes that real-world simulation remains insufficient (each patient has distinct blood vessels and anatomy), so the only way to grow trial volume and speed model improvement is getting more real data from as many hospitals and data silos at once. He stresses that with today's data collection and training processes, collaborative techniques like federated learning already work out-of-box—no need to wait for research breakthroughs.

— Lorenzo

Glossary

Federated Learning
Distributed training that moves the training process to where data lives, keeping data local and off-device.
differential privacy
A technique providing statistical-level privacy guarantees on training results.
interpretability
The ability to understand why a model makes a specific decision or takes a particular step.
trajectory
The complete record from prompt to final output, including all tool calls and intermediate steps.
