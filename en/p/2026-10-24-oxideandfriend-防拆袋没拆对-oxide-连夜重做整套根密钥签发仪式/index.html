Root key trust infrastructure only existed once shipping approached

In fall 2022, after Philip got the hardware ROT functional, he realized he was the only person in the company relying on a PKI that didn't actually exist yet—no one else needed it because no other features depended on this signing infrastructure. The realization wasn't whether to build it but that Oxide suddenly needed to construct an entire external system as complex as the product software itself just to make the hardcoded root key actually trustworthy.

Signing key trust can't follow the lean startup patch-and-iterate model

Lean startup logic says ship an MVP, iterate from customer feedback. Bryan and Philip both noted this doesn't work for signing keys: keys baked into hardware root trust can't realistically be revoked once shipped. Here, ‘minimum’ means living with that decision for many years. The team's goal wasn't perfection—Philip argues perfection shouldn't even be the target, since the design already requires collusion to break the system—but rather finding the minimum acceptable standard that can survive customer and auditor scrutiny.

32:00

Unencrypted signing keys in desk drawers remain disturbingly common

Philip recounted manufacturing horror stories: many startups, rushing to ship, put signing keys directly on a USB stick unencrypted in someone's desk drawer. He estimates this happens far more than zero times. Oxide set a higher bar: keys generated inside an HSM, never leaving the device boundary; only authentication passwords distributed as paper in M-of-N splits, with no single person able to use or compromise the key alone.

— Philip Tricca
53:00

Oxide chose a dot-matrix printer because it's dumb enough to verify

The team selected a dot-matrix printer to print key-split authentication passwords not for sophistication but the opposite—primitive enough to lack wireless, Bluetooth, or anything hidden inside. Opened up, every chip is visible; unlike firmware sealed inside epoxy. The real tradeoff: write-once CD-ROMs resist physical inspection; printers are bulky, messy, don't fit in bank safes, but transparent. After use, this printer was publicly destroyed with a Dremel.

— Philip Tricca
1:00:00

Oxide abandoned traditional Secure Boot because it couldn't prove ongoing trustworthiness

The limited, one-time-write key slots meant the team deliberately avoided traditional Secure Boot architecture. Philip explained that UEFI's Secure Boot assumes ‘code source must be trustworthy,’ but Oxide preferred what Verified Boot offers instead: even if startup code isn't self-signed, if the system can prove ‘the first code executed is observable,’ that establishes trust. The focus isn't whether the source is trusted but whether the state can be audited. Opacity in firmware hides more problems than it solves.

— Philip Tricca
1:07:00

A poorly sealed tamper-evident bag sent Philip back to the office at midnight

After the ceremony, Philip noticed someone's confused expression when opening the tamper-evidence bag—the detail nagged at him. Driving home, anxiety building, he turned around, found a bag, and tested it himself. He discovered he could reseal it without leaving any trace. Those authentication passwords had been ‘protected’ in appearance only for twenty-four hours. The entire key signing ceremony was redone that night using a second printer.

— Philip Tricca
1:16:30

LLMs have compressed nation-state vulnerability discovery into ten minutes

Philip compared this to nuclear proliferation: in the past, identifying certain vulnerability classes required exceptional intelligence and experience concentrated across an industry over extended time. Now an LLM can flip through an old codebase in ten minutes and expose everything. Firmware like UEFI, born in a different era without significant security architecture upgrades, faces the most exposure. The problem deepens: people with these tools often lack vendor relations and responsible disclosure experience.

— Philip Tricca

Glossary

PKI
A trust system based on certificates and the signatures of whoever holds the private key.
Root of Trust (ROT)
The lowest-level security foundation hardcoded into a chip; the source from which the entire chain of trust originates.
Hardware Security Module (HSM)
Dedicated hardware that generates and stores signing keys such that keys never leave the device boundary.
M-of-N key splitting
Dividing a key into N shares such that at least M shares are needed to reconstruct and use the key, preventing any single person from acting alone.
Tamper-evident packaging
Packaging that leaves irreversible traces when opened, used to prove whether contents have been accessed.
Secure Boot / Verified Boot
Secure Boot verifies that startup code comes from a trusted source; Verified Boot only requires proving the startup code's state is unchanged and observable.
