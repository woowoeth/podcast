Ready-made data connectors fail over 40% of the time, forcing OpenAI to build its own pipeline

Testing revealed error rates exceeding 40% on well-known MCP data connectors, pushing OpenAI to abandon third-party integration and build proprietary data pipelines as a core competitive advantage for its financial products.

1:20

Financial products work as consumer ChatGPT plus enterprise layer

ChatGPT for Financial Services is not a new model. It layers industry-specific capabilities—templates, data sources like S&P—on top of the same ChatGPT, co-designed with Morgan Stanley and Evercore. Joseph emphasizes this layering pattern repeatedly: real product value lives in the enterprise customization, not in advancing the base model.

— Joseph Kim
3:45

Codex adoption in finance jumped from 0 to 90%

Internal metrics show Codex adoption among software engineers rose steadily, but adoption in finance, legal, and sales stayed near zero—until Codex shipped a desktop app. Then adoption jumped to 90%. The bottleneck was never capability; it was making capability usable through a product interface.

— Joseph Kim
6:08

Third-party data connectors have over 40% error rates; build them yourself

The team wanted to use existing MCP connectors to ingest financial data. On the surface, it's cheaper—customers already own licenses and MCP subscriptions, so asking for a separate data-integration fee feels wrong. Testing proved otherwise: some well-known MCP connectors had error rates above 40%. The team pulled that work in-house, absorbing the cost. The payoff came in customer feedback, where data quality was the most-mentioned strength.

— Joseph Kim
8:40

Codex gives you 80%; the last 20% is the whole game

Joseph describes his team as operating like a startup built on OpenAI technology. Codex ships with memory, skills, and persistence—enough to get a financial product 80% usable. But wrapping Codex directly as a financial product would fail. That missing 20%—data, UI, integration—is the deciding factor. He sees this pattern (ChatGPT infrastructure plus proprietary secret sauce: data, UI, integration) spawning billion-dollar businesses.

— Joseph Kim
12:00

Design model permissions like onboarding a new employee

How should next-gen agents be governed? Forget new safety frameworks. Reuse what human organizations already do: graduated trust. Like Google's readability credential—new engineers can't submit code in certain languages until they prove they know the codebase—models should have read/write tiers. Go further: borrow the investment-banking hierarchy (analyst, associate, VP, managing director) where every level reviews the next one's work. This mechanism for handling human error scales directly to models.

— Joseph Kim
14:00

The killer isn't factual errors anymore—it's bad taste

Joseph separates two error classes: factual error (cite the wrong number, your whole conclusion collapses, you lose your job) and taste error (ugly slide colors, sloppy layout—non-fatal but damaging to how your work lands). He observes hallucination was a frequent word in 2022–23. Almost never mentioned now. Progress on factual errors is real. Subjective judgment—taste—is what comes next.

— Joseph Kim
16:45

Teach aesthetic judgment through pairwise human comparison

How do you train taste? The answer is strikingly simple: show people two slides, ask which is better, feed the pairwise preference signal into a reward model. This is early-stage RLHF—exactly how it started—which the field neglected while chasing verifiable rewards like "does the code compile?" Here's what surprised Joseph: humans size up a slide's aesthetics in seconds. Let models judge instead, and they burn massive reasoning overhead and still get it wrong. For taste, humans still outscore models.

— Joseph Kim
23:50

Finance benchmarks are broken at scale

Knowledge-work evaluations hit saturation with Astra. The parts still unsaturated are the ones that are broken. The team stopped reporting this metric entirely. There's a pattern internally: score goes up, no one asks questions; score doesn't move, dig into it. GPT-6 didn't shift on some finance evals. Investigation revealed the answer keys were wrong, prompts weren't crisp—the problem was the test, not the model. The team is now building new benchmarks that can predict whether a given job can actually be automated.

— Joseph Kim

Glossary

MCP
Model Context Protocol: standard protocol that lets models connect to external data sources and tools.
RLHF
Reinforcement Learning from Human Feedback; trains models using pairwise human preference comparisons.
reward model
A model trained on human preferences that scores model outputs to guide further training.
readability
Google internal credential; engineers must earn it before submitting code in certain languages.
GDP eval
OpenAI's internal benchmark set for measuring whether knowledge work can be automated.
