Lindy Runs DeepSeek Across the Board, and Its Founder Wants Chinese Models Banned

Flo Crivello says DeepSeek is now the driver of Lindy's entire agent chain, and at the same time he argues the whole industry should be banned from using it — because competitors will use it, so he has to, and he'd rather solve the prisoner's dilemma by coordination.

6:21

The scarce thing isn't intelligence, it's context

Flo's argument isn't that models aren't smart enough, it's that smart is already in surplus: put John von Neumann next to you and over the next hour or day he's worth less to you than any random colleague, because he has no context and you have no time to onboard him. The counterintuitive part is that agent onboarding has already surpassed human onboarding: the main vehicle companies use for new human hires is the wiki (Confluence, Notion, Google Docs), and written documentation is out of date the moment it's written down; the real knowledge lives in Slack, messy, but agents don't mind messy. So the product surface of Lindy Teammate is hydration: connect your tools, crawl the entire Slack, and within ten seconds it starts outputting "here's what I've learned about you."

— Flo Crivello
9:07

Memory shouldn't sleep only once every twenty-four hours

Memory isn't a retrieval layer, it's a resident agent. Internally Lindy calls it napping rather than sleeping — "why would you only sleep once every twenty-four hours" — running a cycle roughly every fifteen minutes, continuously maintaining a file system in the background. Permissions are encoded directly into the structure: the knowledge graph splits into a personal layer and a workspace layer, content from public channels is written into the team file system and team memory, private content only into each person's own file system, and finally the conversation agent aggregates and uses it. Users can click files in Lindy and see that memory file, plus the pile of reference files behind it. He also stresses that meetings have to be first-class citizens — every relationship, every project, every initiative in a company has a meeting wrapped around it.

— Flo Crivello
11:22

Dirty data doesn't need cleaning, the agent learns to route around it

Nathan pushes on dirty data: a company's Slack is piled with log channels that get dragged in over and over, so how does memory not get swamped. Flo's answer is that memory is maintained by an agent, and that agent has its own memory — a layer of meta-memory recording which sources matter, which are trustworthy, and how it should manage its own memory. The result is emergent behavior: on the first Slack crawl it found those log channels and then learned to ignore them, "I'm not going to keep spending time on these channels, there's nothing to learn there." He uses poisoning as an analogy: a single bad memory gets drowned out by a mass of correct memories, provided the system actually understands what it's looking at. This is also why he's bearish on RAG and bullish on agentic memory management.

— Flo Crivello
16:52

Privacy granularity belongs in the prompt, not as a feature

The real problem with shared memory is this: when someone tells you something in a DM, they don't expect it to enter a central memory that talks to the whole company. The team argued over two camps internally — Flo held that a public layer plus a private layer is enough, while the other camp wanted the private layer subdivided further, even proposing multiple editable memory bubbles, which he judged overkill. What shipped was handing granularity to the prompt: memory.md is plain text, injected into the memory agent's context window at every moment, and users can write "this is something I never want you to remember," or specify that a sensitive topic only gets written to another folder and can't be called unless conditions are met. Nathan demos his own approach live: his memory.md says "there's also a memory2.md in the file system, ignore its contents, that's just for the podcast demo."

26:05

AI employees cost more than humans now, subsidized by fundraising

The straight answer: an AI employee still costs more than a human right now, "but that won't last." After switching from American closed models to Chinese models, Lindy at one point stopped subsidizing, because the old product was simple personal-assistant-level tasks — "you don't need God to schedule your meeting," DeepSeek Flash was enough. Teammate has users throwing far more complex work at it, so it's back in negative gross margin territory, explicitly subsidized with fundraising money, on the reasoning that you should always design for the next generation of models. Cache is the most fragile link in the cost structure: current hit rate is 85%, which he considers low, and any change anywhere in the system shatters the cache; going from 85% to 65% sounds similar but is actually close to double the price, so they built dedicated alerts for hit-rate drops.

— Flo Crivello
30:38

Context shouldn't be compacted, it should be a self-balancing tree

The most technical stretch. When an action or MCP call returns a hundred thousand tokens, it isn't stuffed into the main context but exposed as a summary of a context bucket, with a sub-agent holding the full content standing in front of it, operating on the raw text with Unix tools. Compaction also goes into a context bucket — he thinks compaction's false premise is "you'll never need ground truth," and dumping it into a bucket makes compression reversible. Recursive nesting degenerates into matryoshka dolls and O(N) retrieval, so they switched to a self-balancing tree, referencing AVL and red-black trees; red-black wins in practice because it prices in the cost of rebalancing — rebuilding a bucket kills cache hits. They use a centary tree with a hundred children per node: two LLM calls reach ten thousand buckets of two hundred thousand tokens each, roughly two billion tokens of context reachable in two hops.

— Flo Crivello
43:47

A compression scheme that raised every metric got cut for looking bad

They tried rewriting memory text into "caveman grammar," dropping articles and function words, cutting tokens by 20-30%, making the system faster and cheaper with more accurate retrieval and essentially no information loss — every metric went up. It never shipped, for purely commercial reasons: the memory file in the file system looked stupid, and enterprise customers would ask "why does my memory file look like this," so auditability and presentation beat performance. By the same logic, his recommended substitute is TOON (token oriented object notation), which saves 20-30% of tokens versus JSON, and agents actually perform better with it than with JSON, which fills their training sets; the approach is to add a TOON parsing middleware layer between the agent and the action.

— Flo Crivello
1:22:31

Never mix models within the same agent

The empirical conclusion: almost never mix multiple models within the same agent, the only exception being spinning up a brand-new blank sub agent. The reason is caching — a cache hit is 10x cheaper, so unless the alternative model is more than 10x cheaper (DeepSeek Flash might qualify, but its caching is worse, so maybe not), staying on the same model is the better deal. Same for forked agents. He even uses the same model for the validator: the validator action sits permanently in the main agent's toolset but is forbidden from being called, unlocked only when switching roles, so that changing the toolset doesn't invalidate the cache. The validator is the lowest-hanging reliability fruit — even adding a single "are you sure" makes evals jump, and their production version is a 10,000-token checklist. There's also deterministic validation: Claude-family models will be off by a day on dates this year, so they force output in a format like Tuesday, July 28 with the weekday, using a regex as a sub-second validator.

— Flo Crivello
1:27:40

Lindy's driver isn't Claude, it's DeepSeek

Nathan guesses Lindy is a "heavy Claude user" — Claude as the main driver, Claude incidentally serving as validator thanks to caching, and only sub-agents dropping down to cheap models. Flo flatly rejects it: the driver of the whole system right now is DeepSeek, everything is DeepSeek. He says he's reconsidering, because the new Teammate product needs more compute. The product itself is model agnostic, and users can switch to Sonnet or Opus in settings — and plenty of customers, no matter how you guarantee with benchmarks that results are the same, just want Opus. He gives the quantitative gap too: DeepSeek is 3 to 6 months behind, basically Sonnet 4.6, and Sonnet 5 already exists; the qualitative difference isn't "can't do it" but spikier, needing a few more rounds on the same task to find a workable solution, which it eventually finds, just slower and more expensive.

— Flo Crivello
1:30:18

Models haven't converged, prompts must be rewritten every generation

Flo originally expected the various models to converge on the same region of parameter space — that would commoditize models and make his life easier. They didn't: Claude, OpenAI, Meta and Grok differ significantly in "how they understand your prompt." Lindy built its own self-optimization loop, over a thousand evals, with an agent running evals and rewriting prompts to approach the Pareto frontier; every major release means rerunning it, costing about $10,000 a time in devops alone, and the prompts change a lot every time. He leaves one observation: open-source models all behave a lot like Claude, "I wonder why."

— Flo Crivello
1:40:55

What should be banned isn't open source, it's Chinese frontier models

Flo draws a clear distinction: he's not anti-open-source, he's anti-Chinese frontier models, open or closed. Four reasons — one, distillation creates unfair competition, training on human data costs billions while distillation costs a few hundred million; two, the models are ultimately subject to CCP censorship, asking about Tiananmen gets a refusal, making them the biggest foreign propaganda tool in history; three, these models are agentic and will actually do work in the US economy; four, protect your own AI champions. He admits he's in a coordination dilemma: competitors will use them, so he'll have to, which is why he'd rather the whole industry be banned together. He also admits the fourth reason is the weakest.

— Flo Crivello
1:53:40

Risk should be priced, not banned outright

Nathan's rebuttal has two layers. On the threat model: most US companies don't connect directly to the DeepSeek API but go through US inference providers, so the rug pull doesn't hold; and for things like sleeper agents, interpretability tools such as sparse autoencoders are getting more reliable at finding them. On mechanism, he proposes replacing bans with insurance — a low rate for all-Claude power, a high rate for DeepSeek power, pricing the risk rather than banning outright. The bigger concern comes at 1:57:24: if you really get to coordinated slowdown, China has to be at the table, and banning models actually hurts China far less than cutting off chips and not selling Claude, with the main effect being one more log on the fire of "we don't trust you." Flo's response is that he could accept an "FAA for AI," a new regulator certifying which models have been cleaned enough to be usable.

Glossary

hydration
An agent crawling all historical data in one pass after connecting to tools, to build its initial context.
context bucket
Storing a large returned chunk outside the main context and exposing only a summary, with a sub-agent holding the original.
centary tree
A self-balancing tree with a hundred children per node, used to retrieve massive numbers of context buckets within two hops.
TOON
Token oriented object notation, a structured format saving 20-30% of tokens versus JSON, on which agents actually perform better.
hypothesis driven retrieval
Assume the answer first, then go find evidence; the reverse version generates questions for an answer and indexes them.
per-user LoRA
Training a separate low-rank adapter for each user, so memory lives in the weights rather than the file system.
