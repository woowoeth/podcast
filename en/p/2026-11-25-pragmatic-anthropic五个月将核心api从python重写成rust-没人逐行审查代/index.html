Anthropic rewrote its core API from Python to Rust in five months; almost no code was reviewed line-by-line

Validation relied not on reading code but on running shadow traffic between old and new systems to compare outputs; this same approach later rebuilt the agent architecture that cut CPU consumption to one-third.

10:07

CPU became a resource no cloud vendor could sell you in unlimited quantity

Anthropic's earliest API was a Python monolith—built by researchers to work conveniently with model and research code—running in a single GCP region. As request volume exploded, especially after this year's Super Bowl ad campaign, the monolith couldn't handle CPU demand. For the first time in her career, Caitlyn faced a situation where even unlimited spending couldn't buy enough CPU from cloud providers. This forced the team to abandon horizontal scaling and consider rewriting the entire API layer in a lower-level language.

— Caitlyn
22:13

Shadow traffic, not code review, validated the rewrite

Because of data privacy, the team couldn't see raw user requests, making it impossible to directly debug differences between Python and Rust outputs. Their approach: a thin Python façade that shadowed requests to the Rust system, first ensuring pre-inference processing matched, then verifying token counts on return. Day after day they narrowed the gap between systems to nearly zero before removing the façade. Caitlyn noted that roughly 80% of PRs submitted by agents never received line-by-line human review.

— Caitlyn
44:47

Complete rewrites pay off in CPU savings when patching multiplies the cost

The first version launched Cloud Code directly in the sandbox, hitting four problems: sandbox failure killed the agent, startup latency was high, mixing credentials and agent in the same sandbox was unsafe, and each session maxed out CPU. Rather than patching each issue, the team redesigned from first principles: a harness runs on persistent servers, spinning up sandbox only when execution is needed; credentials go in a separate vault, injected only at request exit. The new architecture reduced CPU consumption to roughly one-third of the original. Caitlyn admits ‘deciding to rebuild was definitely a major decision,’ but with implementation costs dropping sharply, it became easier to justify than patching.

— Caitlyn
59:14

Claude now approves routine code changes; humans only see the risky ones

For highly repetitive, predictable changes like SDK version bumps, Anthropic trained a classifier agent to identify what counts as ‘mechanical.’ If it qualifies, another Claude instance reviews it and merges and deploys directly—no human involvement needed. Only changes flagged as risky escalate to humans. The team's explicit goal is to continuously expand the range of changes that pass through unsupervised, rather than settle at the current level.

— Caitlyn
1:06:28

Claude screens every alert for noise before escalating to engineers

For API on-call rotation, Claude receives all alerts first and handles one task only: distinguishing signal from noise. If it's noise, no human gets disturbed. If it's a real problem, Claude escalates to the on-call engineer while simultaneously starting diagnosis; by the time the engineer opens their laptop, they typically have a diagnosis and repair suggestions. The team hasn't yet reached the point where Claude handles real failures independently, but just the ‘is this noise’ filter saves enormous people-time and wake-up calls.

— Caitlyn
1:09:33

Product managers now deploy code; accountability didn't follow capability

The prompt-caching diagnostic feature in the developer console was built entirely through PM-and-Claude dialog in Slack; engineers only reviewed code quality. The line of ‘who can directly deploy’ keeps shifting backward, but when the system breaks, the engineering team that owns it still gets called—not the PM who wrote the code. Accountability didn't move; only the barrier to writing code did.

— Caitlyn
1:23:56

Algorithm interviews stopped working; agent-centric formats are still unproven

Anthropic found candidates often bombing traditional coding interviews while excelling at system design and project retrospectives—the simple reason being they haven't hand-written code in years. The company didn't just delete the interview; instead it's experimenting with agent-centric formats: reviewing agent-written code, evaluating agent system design decisions, running candidates through coding-agent tasks. The goal is finding what actually tests ‘can you use tools to ship things.’

— Caitlyn
1:33:13

The cure for coding anxiety is bigger problems, not smaller ones

Caitlyn traces engineers' identity crisis to their self-concept being built on ‘hand-coding.’ Her answer: scale to multi-agent systems solving real grand challenges—disease, drug approval—but first someone has to solve security, auth, infrastructure at the foundation. Otherwise you just get a fleet of agents shipping larger disasters. Even engineers working with just Claude Max, without frontier-lab budgets, should keep raising their system's ambition rather than stepping back because ‘agents will do it anyway.’

— Caitlyn
