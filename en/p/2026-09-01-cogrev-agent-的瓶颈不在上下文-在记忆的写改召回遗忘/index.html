Agent Bottlenecks Aren't in Context, but in Memory's Write, Change, Recall, Forget

Uber burning through its token budget in 13 weeks proves stuffing context is wrong; MongoDB points to memory as the agent performance bottleneck—write, change, recall, forget—and suggests starting with employee use cases and human-in-the-loop.

Database schemas follow the scarcest resource

Pete anchors on E.F. Codd's 1970 relational model paper: when storage was priciest, normalized tables were rational. By 2007, when MongoDB emerged, the scarce resource had become time, so the document model deliberately denormalized, using JSON/BSON to cut disk reads. He also corrects a misread positioning: MongoDB isn't 'schemaless' but 'schema-flexible'—the same collection can hold documents of different shapes, letting the schema evolve with the product. This design logic shows that database schemas should follow whatever resource is scarcest at the time.

— Pete Johnson
16:38

Stuffing context with data degrades quality

Uber's news of burning through its 2026 token budget in 13 weeks is treated as a failed token-maxing strategy. Cost is only half the problem; quality also drops: research shows the first and last few thousand tokens in a window matter most, the middle is mostly noise. This pushes the industry toward 'classified memory'—selecting only the few terms relevant to the current agent loop each round, rather than replaying all history. The key isn't saving money but that attention decay inside the context makes selective retrieval a performance issue.

23:21

AI features grow from where customers already hurt

MongoDB's search capabilities grew layer by layer from customer pain points: lexical search in 2020 because many customers were building their own Lucene; then vector search because vectors are essentially float arrays and can naturally be a document field; then combining lexical, vector, and metadata pre-filtering into one hybrid search. In 2025, they acquired Voyage AI to bring embedding models in-house, forming a 'better together' offering. This sequence itself shows that infrastructure companies touching AI features typically start from where customers already hurt, not by buying models first and inventing use cases.

— Pete Johnson
40:10

Chunk size tuning should be delegated to the model

The first nagging RAG problem is chunk size: too small, context is insufficient and retrieval quality suffers; too large, storage grows and precision drops, requiring manual trial and error. Voyage's 'contextual chunking' sends the sentence and extra context as two separate strings to the model, which automatically decides the optimal chunk size and returns a single vector. This achieves near-full-context retrieval quality with very small chunks and lower storage cost, now in its fourth version. It's a concrete example of moving the engineer's iterative tuning into the model's weights.

— Pete Johnson
48:20

Embedding models aren't commoditized; selection drives hallucinations

Pete gives two selection thresholds: on scale, you really start to feel pain around 100k vectors; on quality, Voyage leads on Hugging Face's RTEB benchmark, improving retrieval by up to 14% over other embedding models, a gap that can directly manifest as hallucinations. He also reminds that embedding models aren't commoditized—Anthropic doesn't make its own embedding model, so his advice is to use Voyage directly. For many teams, embedding model selection has long been undervalued; this segment puts it back at the center of performance and hallucinations.

— Pete Johnson
1:01:05

Memory has a half-life and must be actively retired

Why is memory hard? Pete's analogy: the industry has been building databases for sixty years, but agents for about eighteen months. Long-term context strategy is no longer stuffing the whole conversation back; it's recalling best context at query time and writing new facts back to memory after answering; enterprise systems also use RBAC to control memory sharing and isolation. He sums up the loop with a colleague's phrase: Write, change, recall, forget. Memory has a half-life—recent information matters more than weeks or months old. This means agent memory must be treated as a first-class citizen, with intentional writing, updating, and retiring.

— Pete Johnson
1:13:10

First wave of enterprise AI lands on employees, not customers

Most Fortune 500 companies Pete talks to are doing employee-facing use cases and keeping humans in the loop. Two reasons: ROI is easier to calculate because these roles already have KPIs; data security consequences are lighter—employee data leaks are easier to handle than customer data leaks. Conversely, fully autonomous customer-facing agents are a worse risk-reward bet right now. This provides a coordinate for enterprise AI budget judgments: the first wave is more likely in internal efficiency tools than in robots making final decisions for customers.

— Pete Johnson

Most sophisticated customers aren't in the US but in Mexico City and São Paulo

Pete met this year's most sophisticated customers in Mexico City and São Paulo, and these customers typically assume US competitors are more advanced. He says what he sees is the opposite. He attributes this to the proliferation of hyperscale data centers and AI services, making geography less important than in the cloud era, leveling global enterprises' access to technology. This observation shows that country labels are increasingly unreliable for judging whether a company can use cutting-edge AI.

Glossary

token maxing
The practice of stuffing as many tokens as the budget allows into the context; costly and quality degrades in the middle.
contextual chunking
Sending a sentence and extra context as two separate inputs to a model, which automatically decides the optimal chunk size and returns a single vector.
Matryoshka embedding
An embedding model that supports truncating high-dimensional vectors to lower dimensions, avoiding re-embedding the entire corpus.
agent skills
Curated system prompts MongoDB provides as markdown files covering topics like data modeling and operations.
