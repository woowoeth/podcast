Burning Tokens to Stack Agents Is a Transitional Strategy, Not the Endgame

Silicon Valley is shifting from mindless token burning to careful budgeting: a local open-source model can do the work for a dollar a day in electricity, but when a genuinely hard problem shows up, one smarter model can still nail in a single shot what a billion-token group chat could not reason out — saving money and top-tier intelligence are not in conflict.

9:06

The era of token-burning leaderboards is over

For the past few months, Silicon Valley's Agent strategy has been called Token Maxing — Jensen Huang asked engineers to burn more tokens, and Meta even set up a leaderboard for who consumed the most. But the wind is shifting: Uber clawed back the token budgets it gave employees after cost overruns, blowing through a full year's budget in 4 months; Stripe's internal tools flatly warn that Opus 4.8 is expensive and suggest cheaper models for non-core tasks first. This episode is about exactly this turning point: how the Agent engineering paradigm moves from mindlessly using the strongest model to using tokens economically.

Four or five hundred dollars a day in tokens is not expensive

Huang Dongxu started using Opus in November last year to build the distributed database db9 from scratch. Even with a $200/month Claude Code Pro Max subscription, once he exceeded the quota he still had to buy extra usage out of pocket, spending four or five hundred dollars a day. His judgment is that the money is worth it — a product that could not be built before because of technical and staffing limits can now be built by one person in three months, and that software could bring the company $10 million a year in direct sales revenue, so the ROI fully covers the token cost.

15:09

OpenClaw's significance is a signal, not a product

Zhang Hongjiang argues that OpenClaw's real significance is not the product itself but the signal it proves: Peter alone spent one week and built an Agent like this, which shows that large models' reasoning and coding abilities have grown strong enough that an architect-level engineer can rapidly assemble a system — it represents AI truly moving from the research stage into the engineering deployment stage. You no longer need a deep understanding of how the model works to build the system you want with it.

— Zhang Hongjiang
23:14

Hermes did not solve memory, it just routed around it

The most criticized problem with OpenClaw is poor memory — it forgets things after context compression and its behavior gets chaotic. After switching to Hermes, Huang Dongxu found it did not solve the memory problem itself but cleverly routed around it: the Agent Loop added a mechanism that continuously summarizes successful experience and solidifies it into reusable skills, so the longer you use it the more best practices grow out of it. He sees this as fundamentally an engineering problem, unrelated to model capability, resting on better architecture design and team polish.

— Huang Dongxu
33:19

Multi-Agent group chats exist to keep the Agent from stopping

Huang Dongxu used Slock to build a multi-Agent discussion group for code review: top models from different vendors pick holes in each other and persuade each other until no one can find another problem, at the cost of 10x the token consumption of a single model — at peak, a billion tokens a day and a bill of three or four hundred dollars. The Slock team calls this mechanism of sustaining an Agent's continuous work through multiple rounds of discussion "Agent dynamics." He argues that in essence every Harness and Loop Engineer is solving the same problem: how do you keep the Agent working nonstop.

— Huang Dongxu
36:21

On single-point hard problems, a stronger model beats multi-Agent

Huang Dongxu originally thought multi-Agent mutual discussion was necessary, because a single model's one-shot success rate was not high enough. But the arrival of GPT-5.5 and Fable 5 broke that assumption: a complex bug the group could not solve after discussing for ages, fed to Fable 5, often gets nailed precisely in one shot — no prior context, purely absolute intelligence crushing it. His conclusion is yes and no: on single-point hard problems a stronger model really does crush collaborative discussion, but extremely hellish problems still need a full Harness as a backstop.

— Huang Dongxu
38:23

Local open-source models can already enter real workflows

DeepSeek V4 and GLM-5.2 made Huang Dongxu trust for the first time that open-source models can enter actual workflows: running DeepSeek V4 Flash locally on a Mac Studio reaches about 30 tokens/s, close to the cloud API experience, and the cost is just electricity and computer depreciation — about $1 a day, twenty or thirty dollars a month. He now hands large batches of repetitive work and tasks he previously did not dare run on paid models (such as summarizing several hundred papers in one go) to the local model, and his bill has dropped from the crazy code-stacking period to two or three hundred dollars a month.

— Huang Dongxu
53:37

Agent startups compete on a data moat, not the model

On whether now is a good time to start an Agent company, Huang Dongxu's judgment is yes, but the key is whether you can hold a moat in enterprise-grade vertical data rather than being crushed at any moment by model capability improvements. He likes three directions: first, middle-layer infrastructure like memory, data platforms and context management; second, observability — being able to answer where the tokens actually go and which are wasted, the question every CIO is asking; third, a new generation of cloud infrastructure built for Agents rather than human developers, such as InsForge, which he invested in.

— Huang Dongxu

Glossary

OpenClaw
An open-source personal-assistant Agent project, advocating local-first and self-held privacy (community nickname ‘crayfish’)
Agentic Loop
The loop mechanism inside an Agent that repeatedly calls the large model, executes tools and updates context
FDE
Forward Deployed Engineer — the engineering team a large-model company stations at enterprise clients to handle Agent deployment
Agent Native
Product design in which the business logic does not hold once AI/Agent is removed — the Agent is the first user
Jevons Paradox
The phenomenon in which, as technological efficiency rises and unit cost falls, total consumption grows even faster
Gödel machine
A system that in theory can prove things about itself, rewrite its own code and continuously self-improve
