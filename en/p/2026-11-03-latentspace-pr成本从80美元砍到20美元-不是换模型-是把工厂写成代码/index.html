Cut PR costs from $80 to $20 not by switching models but by writing the factory as code

After defining its internal software factory entirely as code and wiring in an observability loop, Warp compressed PR costs from $80 to $15–20 through measure-and-optimize, while lifting PR throughput 40%.

2:03

Software factories aren't built by bolting automation together

Zach argues that most companies calling themselves a software factory have simply added some agent-assisted coding—a fundamental misunderstanding. His definition: a cloud-hosted agentic system where teams explicitly define agent roles in the build process, the system exercises autonomy, is measurable and benchmarkable, forms a closed loop, and can be tuned over time to build confidence. That's categorically different from ad-hoc automation.

— Zach Lloyd
4:10

The factory definition itself must run as code

Against the myth that "buy a tool and get a money machine," Zach insists the factory must be concrete and runnable. Define it in YAML: which repos, which MCP integrations, which skills. Write the entire workflow declaratively—like Terraform—so it versions, branches for testing, and rolls back on demand. That's the only way to escape loose automation fragments that can't be versioned or audited.

— Zach Lloyd
6:15

All agent work, wherever it starts, must feed one central system

Whether a task lands in Slack, Linear, or GitHub, it must enter the same system to trigger pre-defined workflows. Only then do you see the complete trace: computer-use screenshots, every orchestration detail, agent-to-agent handoffs. Most companies can't do this because engineers each run Cloud Code or Codex locally, data completely fragmented across laptops and logs.

— Zach Lloyd
14:36

Agents should submit pull requests to improve the factory code

Because the factory definition is code, Warp's self-improving agents analyze historical failures—they spotted 54 cases where the triage agent should have spawned sub-agents but didn't—then submit PRs directly to the factory definition to fix the workflow. It's a complete learning loop, though Zach admits they haven't yet replayed history to verify the fix actually works. That's the next-level capability being built now.

— Zach Lloyd
16:41

Real benchmarks must test model and harness combinations together

Zach argues you can't benchmark models in isolation; you must benchmark models and harness together. Warp runs the same real-world tasks with different model/harness combinations (Warp's own, Cloud Code, Codex, Pi), plots cost-versus-correctness curves, gets results for their specific business rather than generic leaderboards, then feeds those results into model/harness routing strategy.

— Zach Lloyd
23:51

Tuning can cut per-PR costs to one-quarter of starting point

Warp tuned its own system this way: started at ~$80 per PR (too much Opus, over-trained triage models, sub-agents split too finely); brought it down to $15–20. Month-over-month, PR throughput jumped 40% while revert rate stayed flat. Zach calls that the proof that observe-measure-optimize actually works—not just in theory but in the production cost structure of an agentic platform.

— Zach Lloyd
26:58

Teams smaller than five to ten engineers should not use this

Asked who really needs this platform, Zach draws a clear line: small teams just buy Cloud Code or Codex; this platform is overkill for them. The real breakeven is roughly 5–10 engineers and up. Bigger companies need it more, but deployment complexity grows with scale. Growth-stage companies at 10–100 people with Slack and Linear already in place can often self-serve.

— Zach Lloyd
31:07

When API costs are too high, small companies rotate subscriptions

On the hardest objection: some small companies desperately want this system but can't afford it, so they're cycling through $200 subscriptions to piece together capacity, because per-API billing runs 5–50 times more expensive than subscriptions. Zach admits he's unsure whether rotating subscriptions violates the service terms, but concedes it's currently the cheapest way—it just doesn't scale as a company grows.

— Zach Lloyd
33:13

Warp chose agent platforms over token resale because subscriptions subsidize too deeply

Warp chose not to enter the token resale business, Zach explains, because subscription economics are unbeatable: a $200 subscription is worth roughly $8,000 in API value, so a pure API-billing competitor simply can't win on price. Cursor's answer was to pivot to a model lab; Warp's answer was to become an agent optimizer and productivity platform—deliberately not competing in that cost-per-token arena.

— Zach Lloyd

Glossary

software factory
An agentic system defined declaratively as code and running in the cloud, automatically orchestrating product-build workflows in a closed observability loop.
harness
The tooling and orchestration layer that a coding agent runs on; implementations are swappable across different vendors.
scorers / online evals
LLM-based automated scoring mechanisms that judge historical agent runs and surface failure patterns for optimization.
factory engineering
The engineering discipline of optimizing agent systems themselves through measurement and systematic tuning, not intuition.
ADLC / SDLC
Traditional software development lifecycle stages, each replaced by agent-driven equivalents in an agentic system.
