The Pragmatic Engineer 2026-10-29

AI's Real Value Isn't Speed—It's Doing What We Never Dared Imagine

Productivity metrics count code output and bugs, but miss the real shift: teams now solve harder problems they'd previously deemed impractical or impossible. That's precisely why Titus Winters argues AI's impact is wildly underestimated.

The argument · tap a timestamp to hear it

14:27

A production outage forced testing from virtue to non-negotiable rule.

Around 2006–07, Google Search was plagued by regressions. Releases slowed from monthly to quarterly. The system was monolithic—a Gmail change could break Search. Release engineers drew a hard line: no tests, no merge, regardless of VP rank or deadline urgency. After that line, fear stopped being tolerated as an engineering excuse. It had to be technical.

— Titus
22:48

Twelve engineers rewrote a foundation serving 250 million lines without shutdown.

Google's internal C++ base was roughly 250 million lines, with nearly 10,000 engineers modifying it monthly. Titus led a 10–12 person team rebuilding core infrastructure—caches, containers, strings, command-line parsing—everything else depended on it. They described the work as replacing the Empire State Building's foundation while keeping it open to traffic, then discovering nuclear waste in the basement.

— Titus
26:54

Compilers can rewrite code more reliably than humans at scale.

The team didn't manually edit each call site. Instead they parsed code into an Abstract Syntax Tree using Clang/LLVM, matched specific call patterns precisely, then auto-generated edits—a MapReduce-style refactor. Even formatting became blocking; Titus pushed Clang-format, now widely used. The pattern: ship old and new APIs together, migrate directory by directory, delete old code only after verifying no callers remain. This cycle repeated hundreds of times.

— Titus
32:06

AI should write the rules once, not rewrite endlessly.

For large-scale refactors, Titus advises against repeated AI inference. Better: have AI generate a declarative rewrite config (like OpenRewrite)—fix the pattern and transformation once, then run it deterministically across millions of lines. Cheaper, more accurate, more auditable. Kelsey Hightower's principle: if your entire architecture needs continuous inference, a cheaper and more reliable alternative probably exists.

— Titus
52:58

A 15-question survey outpredicts any engineering metric we have.

A brief psychological safety survey predicts roughly 30% of variance in whether a team achieves its goals—stronger than any other signal Titus has encountered. His response: if you believe software engineering excludes emotion, find a stronger predictor. You won't. This isn't a one-time game; it's repeated play. Teams that admit when they're stuck get stronger.

— Titus
1:06:18

Current metrics can't measure the problems AI made worth solving.

Titus sorts technical impact into four categories: product wins, compute efficiency, engineering velocity, and game-changing shifts. Writing a JPEG parser in a few weeks would sound absurd three years ago, but metrics only count throughput, not that you're now building "gold-plated widgets" you never imagined before. Real example: engineers rewrote a third-party component using AI against an existing test suite—work that normally took 5–10 people years and 5–15% annual revenue in licensing fees. The vendor paid to keep it closed. Planned layoffs were canceled.

— Titus
1:12:33

CS curricula were frozen in time around the year 2000.

Titus was the only working engineer on the ACM/IEEE undergraduate curriculum committee. The system was built for nineties-style databases and OSes, then just packed with more topics and diluted. Even before AI arrived, he argued it should burn and restart: less hand-coded linked lists, more systems thinking, specs, and test-driven validation.

— Titus
1:29:29

Evaluate what the student prompted, not what AI wrote.

Students can now AI-complete most assignments. Titus doesn't block it; he adapts. Assume they're using AI; grade the process instead—what prompts did you write, what tests did you write to verify the output? That principle applies beyond CS; nobody needs another ‘Catcher in the Rye’ essay. What matters is whether the student struggled, thought hard, and learned.

— Titus

Glossary

Abseil
Google's open-source C++ library that encapsulates common patterns from their internal code.
Abstract Syntax Tree (AST)
A tree-structured representation of parsed code used to precisely match specific call patterns.
Readability review
Google certification that engineers must pass to approve code changes in a given language.
OpenRewrite
A declarative, configurable batch code refactoring tool widely used in the Java ecosystem.
Zero-token architecture
Design relying on deterministic tools rather than continuous AI inference to complete tasks.
